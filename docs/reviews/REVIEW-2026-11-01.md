# Inkloom 流程、上下文与安全复查

2026-11-01，基于实际代码与隔离测试。保持 **0.2.0 本地测试版**。以下为首次本地复查阶段记录，当时未推送；随后用户授权的前端优化与 GitHub 提交见[前端工程复查](REVIEW-FRONTEND-2026-11-01.md)。两个阶段均没有调用真实收费模型，没有用作者正文或密钥做外部测试，没有发布或操作生产环境。

## 现场与范围

接手时 `git status --short` 与 `git diff` 均为空，分支 `main`，HEAD 为 `84d5e22`。这与交接中“大量未提交修改”的描述不同：正文讨论、轻量场景、复核清单，以及随后的人物关系与微操作已在当前提交中。本轮直接复查这些实现，没有清理或覆盖交接工作；此阶段新增变更先保留在本地工作树。

沿“开书 → 方案/细纲 → 草拟 → 候选采纳 → 定稿记忆 → 后章 → 导出”阅读前后端与数据契约，重点核对版本、资料作用域、任务回执、恢复及手机操作。复用现有工作台与规划讨论概念图；本轮没有确定新的主要页面或整体布局，没有新建场景数据库或多 Agent 写作循环。

## 按优先级确认的问题与处理

严重程度按本机单作者场景判断，需要本地有效会话的操作不描述成公网未鉴权漏洞。

| 优先级 | 复现条件与影响 | 实际处理 |
| --- | --- | --- |
| P1：连接凭证归属 | 编辑已有连接更换端点，或 worker 领取后、实际派发前更改连接，旧地址可能收到另一服务的凭证 | 换端点必须明确清除或重新提供凭证，环境变量引用也不能无意沿用；服务预设/地址切换清除未保存密钥。派发前再次核对连接修订，变更则失败且不发送请求 |
| P1：讨论备份引用 | 恢复时可伪造回复的作品/版本/范围元数据；旧格式也可能被用于夹带新资料 | 实际 user 消息与输入快照一致；v1 禁止正文/档案范围；v2 核对不可变来源，结果引用必须与服务端解析结果一致。拒绝恢复时保持原工作区 |
| P2：后章草拟仍被后端拦截 | 前端已允许继续写，后端仍以 `CANON_GAP` / `CANON_DIRTY` 拒绝，包括轻量场景 | 允许起草并提示最早缺失的可信前文；自动检索仍排除未定稿/待复核正文与记忆，明确必读失效仍拦截，本章定稿仍检查前章顺序 |
| P2：关系召回破坏预算 | 一跳邻居被提升为必读；裁剪人物后仍可能发送指向已移除档案的关系 | 邻居作为有数量上限的可选参考；卡片、关系、实际消息和预览同步裁剪，作者明确必读继续受保护 |
| P2：短选段不能改写 | 工具栏为短句计算 50 字目标，HTTP Schema 却要求至少 100，返回 422 | 统一为至少 50；检查短句、emoji 选段、旧稿冲突与采纳范围 |
| P2：场景未确认提交的参数可变 | 提交回执丢失后，场景字段仍可编辑，而重试使用冻结的原请求，界面与实际参数可能不一致 | 场景全部字段纳入提交锁定；模拟已入队后丢失回执，重试必须逐字段重放同一请求，再检查采纳与旧版本 |
| P2：关系编辑缺少并发保护 | 两窗口编辑或删除同一关系，重复类型造成数据库错误，空白类型造成响应错误 | PUT/DELETE 携带 `base_updated_at`；409 时保留输入并比较最新值，未改字段合并。空白和重复类型返回明确领域错误；单向关系从目标端也可查看 |
| P2：连接与写作 UI 误导 | 本机无鉴权服务被强制要求密钥；预设宣称效果/价格；短续写把 200 字带入整章，文案误称光标插入 | 后端返回 `requires_key`，各生成入口共用连接可用性判断；免密钥仅限明确回环地址。预设改为服务配置起点、费用默认未知；各模式恢复篇幅，短续写明确追加到文末 |
| P2：手机与键盘操作 | 手机全书 SVG 缩小不可读，筛选被全局规则排成长列；节点不能用键盘；部分浅色文字未通过检测 | 手机按人物查看关系列表，筛选紧凑换行；桌面 SVG 支持键盘并提供下拉框。关系加载错误就地重试，讨论长标题收紧，徽标/占位文字对比度修正 |

`base-v2.md` 将人物关系明确为作者设定，保留方向、人物知识与事实边界。旧任务保持冻结的原消息，不回写历史提示词。没有新增数据库迁移；当前关系表迁移仍为 `1b8c6e431fa7`，备份沿线性版本链兼容前七版。

## 三项交接能力的实际状态

[实现说明](../implementation/IMPLEMENTATION-AUTHORING-ASSISTANCE.md) 记录具体路径、截图与边界。

- **正文与档案讨论**：保留最多三章细纲，额外明确选择最多三章正文和十二条作者档案；来源绑定版本、原句校验，资料变化使旧提案失效。历史讨论可能带先前资料引文，不能声称未选择正文时整个请求绝无历史引文。
- **轻量场景**：`SceneIntent` + `scene-v1` 复用 `continue` 任务与候选，采纳后追加并保留旧版；没有独立场景目录、版本或自动节拍系统。
- **复核清单**：只读、元数据分页、版本比较按需读取，能定位明确参考变化并从最早待复核章开始；保持保守失效，不能自动确认后章。

旧 `continue` 的 `scene` 默认值与旧 `discussion` 的空资料默认值不改变幂等语义，原请求返回同一任务，改变范围仍冲突。本轮用回归测试核查已有兼容实现，没有通过重建任务规避回执问题。

README、产品/架构/路线入口及 ADR 0023—0025 已同步。原文中的“从底层杜绝 OOC”、光标插入及未实现的起名脑暴卡片不再作为当前能力或验证结论。

## 各层复查结论

| 范围 | 本轮核对的实际边界 |
| --- | --- |
| 产品流程 | 无模型可手写/保存/历史/导出；AI 开书、细纲、采纳、定稿记忆和下一章通过固定演示走通。草拟与确认事实分开 |
| 前后端与数据模型 | 不可变版本和工作稿基线、细纲/作品/档案修订、候选采纳、关系同书约束与唯一约束。关系接口新增必需并发参数，OpenAPI 已同步 |
| 生成与上下文 | 入队冻结资料与连接；原文依据校验，显式必读与自动资料的预算优先级；关系依赖同步；不自动重发未知调用 |
| 并发与恢复 | 旧请求回执、迟到配置变化、定稿记忆冲突、浏览器恢复副本、断线只读补偿、取消/迟到 worker 与采纳版本检查 |
| 长篇读取 | 目录/历史投影摘要，讨论历史分页，复核清单只读元数据、正文比较按需读取。没有据此宣称百万字性能已达标 |
| 数据与安全 | Host/Origin/本地会话、工作区切换身份、端点与重定向、请求/响应上限、ZIP 解压限额、备份同书快照和新目录恢复；未放宽既有安全检查 |
| UI 与交互 | 桌面 1440×900、手机 390×844 的相关路径、无横向溢出断言、关系键盘操作与局部 axe；不等于全站 WCAG 或全部设备人工验收 |

## 验证与实际限制

详细命令与分轮结果见 [验证记录](../verification/2026-11-01-review.txt)。后端完整 pytest **251 项通过**，前端 Vitest **50 项通过**；Ruff、API 契约与 TypeScript/Vite 构建通过。正文讨论、场景、复核清单及本轮修复相关的浏览器一组 **14 项通过**，文风/选段 **6 项通过**。补充主流程首轮为 **18 通过、3 失败、9 未运行**，失败停在已改名的灵感按钮；恢复简洁文案后，只复测失败或未运行范围及受影响交互，桌面 **5 项**、手机 **13 项**通过。最后补充的场景回执锁定桌面/手机 **2 项通过**。各组有交集，不相加冒充整套测试数；未重跑全部 Playwright 用例。

仍需作者在另行授权后验证真实模型的规划/文学效果、连续十章返工、人物一致性与实际费用。没有进行百万字负载、完整 Windows 中文输入法人工体验或跨浏览器验收；局部自动可访问性检测不能覆盖这些事项。自动召回仍是有限词法与预算策略，改前文仍保守标记后章待复核；这轮修复不构成完全生产可用判断。
