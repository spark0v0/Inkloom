# Inkloom 全项目复查 · 2026-11-12

Inkloom 0.2.0 的开书、规划、手写、候选采纳、逐章定稿与连载导出能在本地形成闭环。本轮优先处理作者输入、已有章节和迟到回执，再改善目录操作与历史资料读取。[实现决策](../decisions/0032-workspace-navigation-and-planning-directory.md)

## 问题与改动

| 优先级 | 复查发现 | 本轮处理 |
| --- | --- | --- |
| 高 | 保存后的目录刷新失败会卸载编辑器。较早的写作打开请求也会在作者已转到其他页面后跳转 | 统一导航和离页保存。后台读取失败时保留正文、焦点与编辑实例。浏览器前进、后退和侧栏切换都检查保存状态，保存期间开始中文组合输入时继续留在原章 |
| 高 | 批量细纲会复用带作者标题或细纲的空白首章。旧卷和新卷的实际章序也会被分卷规划创建顺序掩盖 | 同一本书的首章在写事务内准备。手动创建的首章保留。生成与采纳均检查续接顺序，旧候选如仍要求覆盖已使用的首章则拒绝采纳 |
| 高 | 多步生成、修稿或采纳如果在工作区切换后继续，后续请求可能使用新工作区的默认身份 | 写作与规划的相关请求绑定发起时的工作区。已有的正文版本、细纲修订与任务幂等校验继续约束写入 |
| 中 | 添加正式分卷后，尚无分卷规划的旧章会从规划页消失 | 用独立目录组件合并正式分卷和手稿卷名，支持补分卷规划。手机保留单列，用分卷选择器和两行细纲预览。界面沿用 [工作台概念图](../design/ui-closeout-2026-11-08.png) |
| 中 | 上下文对前文和事实引文逐版查询，重复装载历史编辑器文档 | 单独投影目录与定稿版本元数据，按选中版本批量读取段落。实际章序、作品归属和定稿版本同时约束读取 |
| 中 | 写作页依赖模型配置请求成功，历史与定稿对话框也随写作页下载 | 写作与模型读取解耦。配置异常在助手内重读，手写、保存、查看版本与手动定稿可继续。四个低频对话框按需加载，编辑路由主文件从 502.04 kB 降到 486.40 kB |

## 流程与数据边界复查

- 开书页支持全书方案与直接手写。前文改稿后按版本和章序使后章待复核，复核清单提供变化依据与版本比较。讨论和修稿仍核对同书的指定版本、原句或选区。轻量场景结果走候选采纳，正文版本保留。
- 生成以持久化任务为单位。复查了领取、进度恢复、回执丢失、取消、上下游修订和旧 `continue` / `discuss` 请求回放。供应商执行结果不确定时保留片段，由作者核实后决定是否重试。
- 导出按章序和版本指纹生成清单。备份从一致性快照生成，恢复在新目录核验后切换。当前恢复接受的备份包上限为 64 MiB，数据库解压上限为 256 MiB。架构变更兼容现有 SQLite 格式与备份修订。

## 实现对照

- **MuMuAINovel**（GPL-3.0，`670474f`）的章节上下文服务对本书早于当前章的近期摘要做列投影，也对记忆命中做阈值和少量候选回退。这类减载适合长期维护资料的写作工具。Inkloom 的版本与原文依赖更严格，本轮优化读取开销，仍以有效定稿和原文引文为准。[章节上下文实现](https://github.com/xiamuceer-j/MuMuAINovel/blob/670474fa0fffb51c05e5ea669bc2472af7e4b9ee/backend/app/services/chapter_context_service.py)
- **NovelForge**（AGPL-3.0，`a485814`）按剩余字数为续写轮次分配输出额度，还能按当轮上限截断。本项目的任务与费用边界按作者明确提交计算，多轮生成适合预算、取消与回执都能逐轮呈现的流程。[续写预算实现](https://github.com/RhythmicWave/NovelForge/blob/a485814411546b3980df0a1696a0fb6a043d56ce/backend/app/services/ai/generation/continuation_budget_runtime.py)
- **Novelcrafter** 的 Outline View 将概要排成可折叠的文字列表，便于长篇浏览。Inkloom 在当前分卷层级提供收敛的选择和短摘要，减少手机端目录占用。[官方使用说明](https://www.novelcrafter.com/help/docs/plan/the-outline-view)

对照用于理解机制与交互，代码为独立实现。

## 验证与使用边界

- Ruff、OpenAPI 声明检查、TypeScript 和 Vite 构建通过。Vitest 55 项通过。后端全套 259 项通过，最终续接顺序修订后的生产流程与上下文边界复测 27 项通过。测试使用隔离工作区。
- Playwright 覆盖 74 项桌面与手机模拟用例。首轮通过 68 项。期间修改后端导致已启动的测试服务混用模块，另有旧用例沿用自动进向导的入口。重启隔离服务并修正用例入口后复测 10 项，包含首轮 6 项失败和最后调整的分卷目录流程，均通过。桌面和手机分卷页检查了截图、横向溢出和 axe 规则。
- 对同一份 200 章、949,804 计数字符的合成语料，以 `749349b` 为基准重复组装同一续写任务 3 次。冻结上下文逐项相同，保留旧章线索。单次 SQL 由 59 条降到 16 条，涉及完整 `editor_doc` 的读取由 44 次降到 1 次。组装耗时中位数约 643 ms 与 632 ms。
- 0.2.0 仍是单作者本地测试版。真实模型的文学效果、费用和长期连续创作需要作者实际试写，合成对照只覆盖资料组装。
