# 2026-10-23：模型接入审查与下一步取舍

本轮先将已有 0.2 与 V4、长篇改进同步至 `main`（`74f2ac7`），再检查模型接入、生成响应读取、设置界面、上下文选择与任务列表。以下是有针对性的审查，不代表全仓安全审计或真实模型质量验收。

## 已复现并修复

| 问题 | 实际影响 | 本轮处理 |
| --- | --- | --- |
| 不存在的 Provider 被当成演示模型 | 检查连接错误地报告成功 | 返回明确的 `404 / PROVIDER_NOT_FOUND` |
| 模型目录和正文响应未校验嵌套结构 | 非标准 JSON 可触发内部异常，无法给作者可理解的反馈 | 校验目录、choices、message/delta、正文和结束原因；转为明确的兼容性错误 |
| 非流式响应完整读入后才检查大小 | 大响应可持续占用内存，原有限制生效太晚 | 读取过程中累计字节并中止：正文 4 MB，目录 2 MB |
| SSE 未完成行、连续 data 行缺少完整边界 | 没有换行或事件分隔符的响应可继续积累 | 单行与单事件各限 1 MB，流累计限 16 MB，覆盖未进入正文的 reasoning/心跳数据 |
| 非法端口、IPv6 地址可产生未处理异常 | 保存连接时显示内部错误 | 统一返回地址校验错误 |

响应限制使用十进制字节数；指应用累计读取的解码后数据上限，不是进程内存的绝对上限。异常仍保留生成流程已有的片段与不确定状态处理，不自动重发付费请求。

模型目录请求保持 `follow_redirects=False`、`trust_env=False`，不将凭证跟随重定向交给其他服务，不回显上游错误正文。HTTP 调用从 API 路由移至 Provider 适配层；读取配置后关闭数据库会话，再请求外部服务。

## 接下来最值得做什么

1. **长篇连续性评测（优先）。** 目前工程流程和模拟响应已有验证，但未证明真实模型能稳定写连载。先建立角色已知/未知、前文改稿、伏笔延迟回收、旧设定召回的固定样例，分别记录来源支持率、漏召回、误报、人工评价和成本；有调用授权时再跑真实模型，不用演示结果代替。
2. **作者指定本章参考材料。** 当前有上下文预览和 `excluded_source_ids` 排除机制，尚无完整外部材料库或显式固定参考资料的流程。下一步让作者选择本章必读资料，并区分设定、未来计划、参考材料与已确认事实，显示预算不足时哪些材料未能纳入。
3. **伏笔生命周期。** 目前有 `thread` 类型档案与带依据的伏笔记忆，但缺少“埋下—推进—回收”的结构化状态及关联章节。应随定稿确认并在前文修改后失效，而不是让 AI 自行勾选“已回收”。
4. **任务历史分页和查询瘦身。** `Generation.list()` 当前加载完整 Job ORM 对象，最多返回最近 150 条；前端没有游标翻页。长篇生成历史需要分页，列表查询也应避免读取上下文等大字段。本轮未测量大量任务的性能，不将其描述为已经发生的卡顿。
5. **调用总时限。** 现有网络读取超时与本轮流大小限制不能等同于整次调用的总时间上限。可进一步增加可配置总时限，超时保留片段与上游不确定状态；先覆盖慢心跳等用例，再确定默认值。

这些是后续优先级，不是本轮已经实现的功能。暂不迁移技术栈、引入独立向量数据库或增加新布局。
