# UI 概念与实现规范

设计方向：面向持续写作的中文作者，以正文为中心，采用克制的编辑出版语言。森林绿提供动作层级，灰白底降低视觉噪声，正文与工具界面有明确的排版差异。

视觉变化 4/10、动效 2/10、信息密度 6/10。这里的“文学感”来自可读的书稿、资料与引用，而非装饰性书封、古风纹理或营销标语。

## 设计参考的适用范围

使用 `ui-ux-pro-max` 查询了 `novel writing editor productivity`，返回极简/瑞士风格等通用建议，但布局部分偏营销单列；随后 `writing note taking` 的 product 查询返回零匹配。因此，**没有把检索结果当作经过验证的小说工作台方案**，也没有保存错配的通用设计系统。

`design-taste-frontend` 自身声明不适用于密集工作台和多步骤产品 UI；本项目只采用减少模板感、保持视觉一致性的相关原则，实际信息架构、布局和交互由创作流程决定。字体、颜色与三栏设计属于本项目的设计选择，不声称来自精确匹配的数据库结果。

## 视觉 token

推荐初版变量，实际组件使用语义 token，不散落硬编码颜色：

```css
:root {
  --canvas: #f7f8f5;
  --surface: #fcfcfa;
  --surface-muted: #f0f3ef;
  --ink: #202823;
  --text-secondary: #667269;
  --accent: #315847;
  --accent-text: #ffffff;
  --accent-soft: #e7efe8;
  --border: #dde3dc;
  --control-border: #7b887e;
  --warning-text: #87520f;
  --warning-bg: #fff4de;
  --danger: #a33737;
  --focus-ring: #315847;
  --radius-control: 8px;
  --radius-panel: 12px;
  --radius-sheet: 16px;
  --space-1: 4px;
  --space-2: 8px;
  --space-3: 12px;
  --space-4: 16px;
  --space-6: 24px;
  --space-8: 32px;
}
```

绿色只承担主动作、选中、链接和真实成功状态；警告与危险各有语义色，不能为保持单一强调色而让错误信息难辨认。细分隔线可以低对比，输入框/控件边界与焦点需单独满足可识别性要求。

主按钮使用深绿底白字；次按钮用边框和深色字；破坏性按钮只在需要时出现。禁止将 placeholder 当作唯一标签或用颜色表达全部状态。图片只作颜色方向参考，最终对比度以实际 token 和组件状态测量。

初版只交付经过验证的浅色主题；暗色主题作为 P1，需完整设计与对比度验证，不能用一键反色冒充。

## 字体与正文阅读

- UI：系统中文无衬线优先，`Noto Sans SC` / `Microsoft YaHei` / `PingFang SC` / `sans-serif`。界面常规字号 14—16px，辅助信息原则上不低于 12px。
- 正文：`Noto Serif SC` / `Source Han Serif SC` / `Songti SC` / `SimSun` / `serif`，默认约 20px，允许 16—24px 调整；正文行高约 1.85，阅读宽度约 32—38 个汉字。
- 页面标题约 24—28px；章节标题约 28—32px。移动端可缩到约 24px 并自然换行，不能从生图像素直接推导 CSS 字号。
- 字体可使用系统回退；若自托管字体需核验许可、控制中文字体体积并设置 `font-display: swap`。不让外网字体加载成为离线写作前置条件。
- 段落缩进、段距、字体和阅读宽度可作为偏好保存，不能通过正文插入多余空格来伪造排版。
- 统计默认采用 Unicode code point 中的非空白字符数，**含标点**；UI 的“字”需有说明。可另显汉字/英文词统计，但目标长度必须注明采用哪种口径。前后端用同一组边界样例校验。

## 桌面写作页

建议在 1440px 视口采用 `64px 232px minmax(480px, 1fr) 320px` 的整体分区，正文容器内部设置阅读最大宽度；具体值以真实文本、缩放和可访问性验证调整。

1. 顶栏：品牌/回书架、当前作品、导航位置、命令搜索、专注模式与导出。长标题截断可访问完整名称；小屏降低顶栏信息量。
2. 左导航：创作、故事档案、剧情、任务、设置；图标一致且有文字或可访问名称。
3. 目录：卷/章树、当前选中、草稿/已确认状态、字数和新建入口；下方本章目标可编辑。章顺序不能只靠拖拽，提供键盘或按钮替代。
4. 正文：独立可滚动编辑区，显示草稿/确认状态、选段与引用标记。旁注不能压住文字；不把大聊天窗口盖在正文上。
5. 右栏：写作助手/上下文，输入本次要求、任务操作、来源清单和待核实项。未配置时明确状态；没有选区时禁用“润色选段”并解释。
6. 底部：真实字数、保存状态、版本/时间与任务相关状态。不在未收到持久化确认前显示已保存。

专注模式收起目录与助手，保留退出、当前标题和保存状态。退出还原先前面板宽度和选中章节，不重置光标。

`Ctrl/Cmd+K` 打开作品内命令/搜索；`Ctrl/Cmd+S` 保存。快捷键冲突时提供常规按钮；IME 组合期间不能把 Enter 当执行生成。

## 故事档案页

沿用同一外壳，顶部人物/世界/伏笔/时间线切换。左列表、中间详情、右来源检查器；尺寸不足时优先让来源转为抽屉。

- 固定设定、当前状态、人物知道什么分别组织；显示“截至第几章/哪个修订”。
- 原文链接打开指定版本与段落，不把当前工作稿中相似句子当作旧引用。
- 已确认、候选、未知、失效都有文字标识。未知信息不是“否定事实”。
- 待确认变更显示影响、依据和作者处理入口；“有意安排”需要记录范围，不能让后续所有审稿永久忽略同类问题。
- P0 采用真实列表和关系记录即可；复杂可视关系图是 P1，不因竞品已有图谱就占据默认写作空间。

## 移动布局与候选采纳

| 宽度 | 行为 |
| --- | --- |
| ≥1280px | 目录、正文与助手可并列，面板可折叠 |
| 1024—1279px | 优先收起助手，以抽屉展开；保持正文阅读宽度 |
| 768—1023px | 默认正文单主区，目录/助手按需开启，避免多层抽屉叠加 |
| <768px | 单列写作，目录抽屉、助手/候选底部面板；顶部保留返回与章节入口 |

窄屏差异比较上下堆叠，不并排挤压。候选面板包含原文基线、新建议、上下文状态和“保留原稿/采纳为新版本”。候选很长时内容区滚动，动作区固定在安全区域内。

面板打开时管理焦点、背景滚动和读屏标题；关闭回到触发控件。虚拟键盘、200% 缩放和横屏不能挡住动作；底部留 `safe-area-inset-bottom`。长文本对比需要能查看全文，不能只显示截断后的两句话。

手机响应式并不等于云同步。P0 默认回环地址，窄屏可用浏览器模拟验证；后续真机通过局域网/远程访问须先设计会话与部署边界。

## 完整状态文案

| 状态 | 建议文案/行为 |
| --- | --- |
| 空作品 | “从第一章开始”，新建/导入入口可直接使用 |
| 缺模型 | “尚未配置模型”，允许继续手写；演示入口独立标记 |
| 保存中/失败 | “正在保存…” / “尚未保存，内容仍在当前页面”，给出重试与恢复导出 |
| 保存冲突 | “此章已有新版本”，比较双方文本；不自动覆盖 |
| 生成中 | 显示真实阶段和流入内容，允许取消；不显示伪百分比 |
| 暂停中 | “本次调用结束后暂停”，不暗示已停止计费 |
| 流中断 | “生成中断，已保留部分内容”，明确上游执行可能未知 |
| 已取消 | 保留部分稿，后续结果不能突然变为成功可采纳稿 |
| 候选过期 | “原稿或参考资料已更新”，比较后重建基线 |
| 正史待复核 | 显示从哪章开始受影响、哪些自动操作暂停 |
| 来源失效 | 显示旧版本与原因，不能当有效事实继续注入 |
| 费用未知 | “未配置价格”或“服务未返回用量”，不填 0 元 |

`aria-live` 用于任务关键状态和保存状态，避免每个流式 token 触发读屏。动效约 120—200ms，仅用于面板/状态反馈；尊重减少动态效果偏好，不增加写作区漂浮动画。

## 从概念图到代码时必须补正的内容

生图已经表达视觉意图，仍不应机械照抄以下示例细节：

1. 图中只展示部分正文，`2,340 字` 不是可复算的真实计数；实现必须用当前文档计算，初始演示也需按实际内容统计。
2. 档案图中的“雨夜访客”来自第七章草稿，列表应加“候选/未确认”标识，不能让它看起来已在第六章正史确立。
3. 桌面图未完整表现“采纳”和“确认为正史”两个步骤，需要按产品规范补上状态和入口；不能把采纳直接当确认。
4. 移动图只表现基线一致状态；冲突、来源过期和部分稿状态必须另实现。不能把图上的一致提示硬编码。
5. “本次参考”的短描述可与章节标题不同，但底层必须链接正确章节/版本/段落，不能依靠显示名称匹配。
6. 浅色分隔线不一定满足输入控件边界要求；实现使用强边界 token 与可见焦点，逐状态测量对比度。
7. 原文引用只在有实际记录时出现；没有资料时显示空状态，不用硬编码小说设定凑满页面。

## 实现映射与视觉验收

建议组件边界：`WorkspaceShell`、`ChapterTree`、`ManuscriptEditor`、`SaveStatus`、`AssistantPanel`、`ContextInspector`、`CandidateReview`、`CanonChangePreview`、`EntityDossier`、`EvidenceInspector`、`JobStatus`。

命名仅为职责建议，不强制提前造完组件。先实现数据和核心操作，再比对参考图的层级、字重、间距、正文宽度和面板尺寸。图像相似度不能取代功能与可访问性验收。

交付 UI 时至少保存桌面、窄屏、候选与失败状态的真实页面截图，记录视口与代码版本。本轮提供的是生成概念图，**尚未进行浏览器、输入法或页面可访问性验证**。
