# 2026-10-24：连载可用性审查与竞品对照

目标是让单个作者接入自己的模型，持续完成可审阅、可修改、可追溯和可导出的长篇连载。当前工程闭环不等于真实模型已达到连载质量。本轮先审查资料召回、候选稿、重试、模型选择与备份升级，再确定实现范围。

## 代码审查发现与本轮处理

1. **作者不能明确指定本章必读（功能缺口）。** 原 `context.py` 只有自动召回与排除来源，较早的关键资料可能没有命中。新增章节级参考选择、前文版本绑定、补充资料与持久化；必读不被可选裁剪删除，预算不足在发送前报错。
2. **候选目标字数显示错误（P2）。** `Assistant.tsx` 从作品默认 `chapter_words` 取目标，不能代表创建该任务时的实际要求。改为显示冻结的 `target_chars`，旧任务从冻结输入兼容恢复，未知就标未知。
3. **重试后的旧片段缺少产品入口（P2）。** `jobs.py` 已保存每次 Attempt 的 `output_text`，但界面只展示当前任务结果和调用状态，重试清空当前结果后无法直接找回前次片段。提供逐次只读查看与下载，不将未完成片段变成可直接采纳的完整稿。
4. **切换写作方式会重置模型（P2）。** `changeTask()` 无条件重新读取默认模型，作者手选连接后切换续写可能变回演示连接。已按任务角色保留本次打开工作区后的手动选择；切换写作方式、找灵感与返回写作不再重置选择，切换本身不调用模型。刷新后仍从模型设置的默认值初始化，恢复已有灵感任务时使用其来源模型。
5. **缺少带预期答案的连续性评测入口。** 新增八组本项目自编的固定样例与可重复运行的独立 SQLite runner，检查旧资料、别名、短词、跨作品、未来章节、失效与非正史材料。它不评判文学效果，不发送模型请求。

新选择引入 `b73d2f809a61` 增量迁移，保留原稿与旧任务；旧备份在新目录验证后升级。升级现有本地工作区前，先留存一致性 ZIP 备份，并在独立目录验证正文、引用与迁移，不删除数据库解决升级问题。

## 距离真实连载仍缺什么

| 优先级 | 缺口 | 可验证的后续验收 |
| --- | --- | --- |
| 最高 | 真实模型质量与接入验收 | 用实际连接连续写作和修改至少十章，保留原稿、调用、费用与人工判断；本机目前只配置了 Demo，不能作出真实质量结论 |
| 高 | 审稿问题到局部改写 | 选定一条有依据的问题，准备对应选段修订；作者确认生成和采纳，旧稿及出处保留 |
| 高 | 伏笔生命周期和角色状态演变 | 埋下、推进、回收均关联定稿证据，前文修改后正确失效；不将未来计划或模型自评当事实 |
| 中 | 完整历史分页和搜索 | 超过 150 条任务仍可找到早期候选；列表不加载完整上下文。当前按章恢复与列表瘦身已有，完整历史分页尚未实现 |
| 中 | 可复用的外部材料库与总调用时限 | 本轮补充资料按章保存，不宣称完整文档知识库；长心跳、慢响应仍需要整次调用总时限的独立验证 |

浏览器验证还发现参考窗口可能使用缓存的旧章节目录：后端已拒绝失效参考，界面却没有给出重新确认入口。窗口现在打开时重新读取章节、设定与已保存选择，读完后才允许编辑和保存；刷新读取不覆盖作者已经开始修改的选择。

以实际使用任务和证据决定后续改动，暂不引入新的微服务、向量服务、自由运行多 Agent 或自动平台发布。实现细节与最终验证见 [本轮交付记录](IMPLEMENTATION-REFERENCES.md)。
