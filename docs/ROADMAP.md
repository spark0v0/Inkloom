# 开发路线与交付边界

最初 M0 交付见 `docs/DELIVERY.md`。目前已有 0.1.0 本地测试版，覆盖 M1—M3 核心工程流程与 M4 的部分自动验证；真实输入法人工检查、真实 Provider 与长篇文学评测仍未完成，不能将 M4 全部打勾。实际能力与证据见 [IMPLEMENTATION.md](IMPLEMENTATION.md)。以下保留各阶段的完整目标。

按依赖推进，每个里程碑都交付能实际操作的纵向流程。不要先铺设所有菜单与假接口，再把“剩余接后端”当小尾项。工期以完成首个纵向流程后的实际速度估算，本方案不提供未经验证的日期承诺。

## M0：产品与工程设计

交付：9 个仓库与 6 个论坛讨论的研究摘要、来源快照、产品/技术方案、`AGENTS.md`、开发启动提示词、运行时提示词、验收方案、三张生图 UI 和对应设计规范。

退出条件：引用来源明确，方案区分事实与推论，文档相互链接有效，图片已保存到项目，当前实现状态不夸大。此阶段不声称任何模型质量或软件功能验证通过。

## M1：没有 AI 也能可靠写作

**纵向目标：** 新建作品 → 新建章节 → 输入 → 保存 → 关闭重开 → 查看旧版本 → 导出 → 备份 → 新目录恢复。

实施顺序：

1. 建立前后端最小工程、锁文件、同源运行方式和 PowerShell 启动入口；初始化迁移和临时 SQLite 集成测试。
2. 先完成作品、章节、不可变正文版本、基线检查与错误 Schema，再建立编辑器页面。
3. 查看现有写作概念图，实现真实目录、编辑器、保存状态和可折叠侧栏；AI 区域未接入时明确显示“尚未接入”。
4. 验证中文输入法、自动保存请求顺序、本地恢复缓存、并发冲突与离线反馈。
5. 加入 TXT/Markdown 编码/切分预览、版本选择导出与一致性备份恢复。

验收入口：[ACCEPTANCE.md](ACCEPTANCE.md) 的 A01—A06、A20—A22。没有数据库持久化、只有浏览器静态示例的页面不能视为 M1。

## M2：可控的 AI 候选稿闭环

**纵向目标：** 配置 Provider → 查看上下文 → 创建任务 → 流式候选 → 比较 → 采纳为新版本 → 原稿可恢复。

实施顺序：

1. 明确 Provider 能力、凭证边界、任务/Attempt/调用状态、幂等键与预算策略，完成持久化 worker 领取和事件日志。
2. 通过显著标记的 Demo Provider 和本地协议测试服务器验证真实 SSE/结构化错误流程；这两者都不代表真实模型质量。
3. 实现 OpenAI-compatible transport 的配置与能力校验，不预设所有中转站行为一致。服务不可用要返回真实错误。
4. 完成续写/选段改写的候选生成、版本对比与安全采纳。移动候选面板按现有概念图实现。
5. 加入取消、边界暂停、恢复、未知上游执行、使用量缺失和有限重试。
6. 在用户已有本地配置与调用授权时做最小真实服务验证，记录模型与参数。无配置时交付可接入实现，明确标注“真实服务未验证”。

验收入口：A07—A13、A23。仅有生成按钮和 toast、原稿被直接替换、刷新就重跑任务，均不能视为完成。

## M3：可追溯正史与中文长篇记忆

**纵向目标：** 人物/设定与简报 → 生成一章候选 → 作者采纳 → 事实提议 → 原文依据校验 → 确认正史 → 下一章引用 → 修改前文并正确失效。

实施顺序：

1. 建立正史修订、人物别名、段落来源、知识记录、基础伏笔与章序/故事时间契约。
2. 实现最简资料与剧情编辑、事实提议/确认面板；故事档案依据现有概念图，不先做复杂关系图。
3. 完成原文/事实的作用域索引、短中文词回退、上下文分层与来源清单。
4. 实现正文修订后的后缀失效与可信前缀重建，防止历史事实继续作为当前记忆。
5. 实现基础一致性审稿，允许未知、有意安排和误报，不自动将评分转成发布许可。
6. 用带标准答案的微场景验证工程契约，再进入真实模型小样本评测。

验收入口：A14—A19，以及 R 类模型评测。Prompt 中写了“保证一致性”不能替代来源绑定和失效测试。

## M4：把首版变成可持续使用的软件

**纵向目标：** 一个十章样例的完整工程流程，加上真实模型与作者反馈的独立验证记录。

实施顺序：

1. 串起十章演示闭环，并修改第 3 章，逐章复核下游；演示和真实调用始终分别标记。
2. 注入断线、dispatch 后崩溃、重复采纳、旧 worker 迟到、磁盘错误、损坏导入和恢复异常。
3. 检查 1440/1024/768/390 宽度、键盘焦点、中文输入、长标题、万字章节、空项目和失败流程。
4. 测量约定设备下的编辑与检索性能，生成必要截图，修正概念图未覆盖的真实状态。
5. 检查发布包、日志与导出不泄露凭证；编写安装、备份、恢复、升级、错误排查与真实 Provider 支持情况。
6. 有调用授权和作者样本时进行盲评；没有这些证据时明确将文学效果列为未验证，不发布虚构质量百分比。

退出条件分别记录，不能合并成一个“已完成”标记：

| 验证域 | 需要的证据 |
| --- | --- |
| 工程可用性 | 相关自动检查、浏览器核心流程、故障注入和恢复对比 |
| 真实 Provider 可用性 | 实际 endpoint/模型/日期/参数/调用结果及脱敏记录 |
| 作者体验 | 有具体任务的观察记录、耗时、返工点和可理解性反馈 |
| 文学与长篇效果 | 人评、来源支持性、误报、成本和对照实验，注明样本限制 |

没有完成全部验证域时，可以交付明确标识验证范围的测试版；不能称作已经证明“高质量全自动长篇生产”。公开发布仍需本轮任务明确授权。

## P1：经过使用验证后的增强

按反馈选择，不自动全部开展：

- 作者经常反复人工查找远处情节 → 评测语义检索与精细依赖失效。
- 伏笔整理确实成为负担 → 时间线/伏笔可视视图、关系图与故事弧追踪。
- 既有真实服务覆盖不足 → 原生协议适配与明确兼容矩阵。
- 选段文风难保持 → 作者自有样例的可执行风格指南与对照评测。
- 手动逐章确认负担可测量 → 有预算、有检查点、可暂停的有限多章批次。
- 外部交稿需求明确 → DOCX/EPUB、版式与导出恢复检查。

暗色主题、全局搜索增强和桌面便携发行也在此阶段按实际需求安排；新增主要视觉页面先补生图概念。

## P2：独立立项的扩展

完整剧情分支、多人协作、身份权限、云同步、移动离线同步、插件市场、联网工具、自动发布与工作室商业化。这些涉及新的数据合并、安全和部署边界，不能混入首版任务以“顺便实现”。

## 后续开发的记录规则

每个里程碑记录：实际实现、实际检查命令与结果、人工验证环境、真实模型调用情况、已知缺口。文档和界面只能展示已经存在的能力；未来能力使用“计划/未接入”，不能依靠演示数据伪装。

根目录 `START_PROMPT.md` 可直接启动下一阶段；新的用户范围变更应同步到这里和相关产品/架构契约。
