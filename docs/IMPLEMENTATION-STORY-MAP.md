# 故事脉络：实现与验证

2026-10-30。本轮参考 Novelcrafter 的规划视图及开源项目的资料组织方式，补齐跨章节查看和定位入口；对照范围与后续缺口见 [调研记录](REVIEW-2026-10-30.md)，数据边界见 [决策 0017](decisions/0017-story-map.md)。

## 实际功能

- 在 **大纲与章节 → 故事脉络** 按章节顺序查看细纲、创作/定稿状态，以及关联的伏笔计划和正文进展。
- 计划回收、暂缓计划、有效的埋设/推进/回收、旧版本待复核分别显示。计划不表示正文已发生，已撤销记录不进入默认脉络。旧依据仍可打开对应版本原文。
- 按卷、章节状态、伏笔和关键词筛选；关键词覆盖章名、细纲、伏笔名与别名，兼容全角输入。40 章一页，翻页后焦点移到首章，避免一次渲染整个长目录。
- 从卡片进入现有细纲编辑器，保存后可返回脉络；伏笔名称打开对应档案，刷新保留深链接。没有另建一份需要人工同步的图数据。
- 桌面提供右侧伏笔索引，手机采用单列与可收起筛选。空目录、无匹配内容、首次读取失败和刷新失败均有就近反馈；刷新失败保留已取得的内容并可重试。

## 实现与设计

`storyMap.ts` 是不修改输入的投影与筛选函数。除服务端 `valid` 标记外，再检查章节处于定稿状态、记录版本等于当前定稿版本，避免独立读取的两份缓存暂时不同步时误显示有效进展。归属不符、找不到章节和已撤销的记录不挂入其他章节。

`StoryMap.tsx` 读取既有章节与伏笔 API；`route.ts` 增加展示用查询参数，兼容旧链接。细纲编辑与伏笔档案复用原有保存、版本校验和原文查看流程。没有后端、数据库迁移、依赖、生成提示词或备份格式变更。

浏览器验证还复现并修复了一个共享查询错误：脉络刷新章节失败会触发 App 中原本面向写作入口的全局错误页，导致已有内容消失。现将这层错误判断限定到写作页，规划页优先交由脉络组件呈现自己的读取状态。首次加载失败仍显示错误，保留内容不冒充刷新成功。

## 实际验证

- `npm --prefix frontend run build`：TypeScript 检查与 Vite 构建通过。
- `npm --prefix frontend test -- src/lib/storyMap.test.ts src/lib/route.test.ts`：2 个文件、7 项通过。覆盖归属隔离、非破坏排序、计划与进展分离、版本失效、撤销记录、组合筛选及旧/新深链接。
- `npm --prefix frontend run test:e2e -- story-map.spec.ts`：桌面和手机两个场景通过。使用 41 章的临时 SQLite 工作区，覆盖分页、焦点、筛选、旧版原文、编辑后返回、伏笔深链刷新，以及章节/伏笔接口分别失败后的内容保留与重试恢复。断言没有创建生成任务，细纲编辑未改变正文版本。
- 同一浏览器场景中的 axe 指定 WCAG 2/2.1/2.2 AA 自动规则未发现违规，检查宽度未溢出；已查看桌面、平板宽度和手机截图。这不代表全站无障碍审计或实体手机、输入法验收通过。

首次检查发现列表中卷标题的 HTML 语义问题，已修正；新增章节接口失败场景又复现了上述全局错误页问题，修复后最终定向验证通过。未重复运行无关的后端全套检查。

## 当前边界

脉络按章节叙事顺序排列，不推断故事内时间、人物关系或未有依据的剧情事实。页面最多渲染 40 章，但仍使用已有目录/伏笔读取接口，不宣称完成后端分页或百万字性能验收。

持续规划聊天、章内场景编排、跨章修改提案仍待实现。本轮没有调用真实写作模型；连续十章的文学质量、人物一致性、作者返工量和实际费用仍待获得调用授权后验证。
