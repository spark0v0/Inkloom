# 产品方案

## 0.2 的当前主线

用户的明确目标是利用接入的 AI 模型，从创意创作并持续连载一部长篇小说。默认入口已调整为 AI 全书策划、按卷分批细纲、整章生成、采纳、定稿与下一章、按章导出。作者不必预先手写大纲、人物和章节；对方案与正文保留最终决定权。界面不再要求先理解正史修订、任务状态等内部概念。

写作中卡剧情时，当前工作区提供“找灵感”：比较三个未来方向，选中后明确点击续写生成候选。细节见 [剧情灵感决策](decisions/0007-in-chapter-inspiration.md)。

需要明确引用旧情节时，使用“本章参考”选择本书设定与此前定稿，或填写非正史的研究资料；保存不调用模型。前文版本改变后要求重新确认，必读不静默丢弃。生成重试后仍可查看并下载各次保留片段，切换写作方式保留本次按角色选择的模型。实现与验证见 [本章参考记录](IMPLEMENTATION-REFERENCES.md)。

产品名统一为 **Inkloom**；当前实现与边界见 [0.2 记录](IMPLEMENTATION-V0.2.md)，布局见 [V4 UI](design/IMPLEMENTATION-V4.md)。下文中的首版范围与旧工作名保留为早期设计背景；冲突时以本节和用户最新要求为准。

## 定位与成功标准

叙事工坊帮助中文小说作者把灵感、设定、正文与已发生的故事放进同一个可靠工作区。AI 可以给出建议和候选，作者决定采用什么、哪些内容进入正史。

首版成功标准是：作者能连续完成十章，改写前文后仍能理解影响、继续创作、取回旧稿并导出完整作品。**0.1.0 已实现对应工程闭环与十章演示回归；真实作者体验、长篇质量和性能仍待独立测量。** 不以一键生成的字数、界面功能数量或模型自评分作为成功证据。

目标用户优先级：

1. 有自己的故事方向、希望 AI 协助打磨的作者。
2. 需要维护人物、伏笔和连续性的中文连载作者。
3. 已有部分手稿，希望整理资料或接续写作的作者。

首版默认单用户、本地工作区、网页界面、用户自带模型服务。先支持 Windows 原生开发与运行；浏览器界面保留桌面和手机布局能力。手机布局适配不等于已交付多端同步或公网访问。

## 五个产品承诺

| 承诺 | 用户能看到的行为 |
| --- | --- |
| 内容由我控制 | AI 先给候选，可比较、调整、拒绝或采纳；原稿版本始终保留 |
| 我的文字不会被静默覆盖 | 自动保存显示真实状态；版本冲突保留双方内容；恢复和备份有明确入口 |
| 记忆有据可查 | 人物状态、伏笔和审稿意见可点回指定版本的原文 |
| 我知道发生了什么 | 看得到本次参考、生成阶段、错误原因、用量及费用是否未知 |
| 工具不会绑架作品 | 无 Key 也能手写，随时导出 TXT/Markdown，完整备份能在新目录恢复 |

## 信息架构

书架负责作品创建、打开、最近编辑与导入。进入作品后只有五个一级工作入口，与 UI 概念图一致：

| 入口 | 主要内容 | 首版边界 |
| --- | --- | --- |
| 创作 | 章目录、正文、候选稿、助手、上下文与版本 | 核心工作区域，默认打开上次章节 |
| 故事档案 | 人物、世界、基础伏笔、故事时间记录与来源 | 列表和详情即可；关系图是 P1 |
| 剧情 | 简报、卷纲、章纲、场景目标和待办线索 | 支持编辑与引用，不要求掌握节点编排 |
| 任务 | 活动/历史任务、部分稿、错误、取消和恢复 | 历史不丢失，进度由真实事件驱动 |
| 设置 | Provider、模型角色、写作偏好、工作区、备份 | 高级配置渐进展开，不挡住第一段写作 |

不要另造一套每个功能都跳转的“数据大屏”。侧栏模块可被深链接和命令搜索访问；写作时优先保留正文空间。

## 核心使用流程

### 1. 第一次进入

用户可以选择“新建空白作品”“从一句创意开始”或“导入已有手稿”。至少填写作品名即可进编辑器；类型、读者、题材、长度与文风可以稍后补齐。

没有模型配置时照常写作；需要 AI 的操作显示“配置模型”或显著标记的“试用演示”，不能自动切到假生成。演示作品与真实作品相互隔离，用户可直接创建空作品。

初次体验目标是在五分钟内完成新建、手写、保存和导出；实际时间需要用户任务测试后记录。

### 2. 整理作品方向

创作简报记录一句话前提、核心冲突、角色欲望、题材、叙述视角、文风与作者边界。字段可留空，不能要求几十项设定齐全才允许写第一章。

分层规划采用“作品 → 卷 → 章 → 场景意图”。不强制每个作品都有卷，也不强制逐场景建卡。未来计划保存在计划区，不进入“已发生事实”。

允许从任意位置修改草稿；自动“继续下一章”需要有清晰可用的正史前缀，而手工写作没有这一限制。

### 3. 写一章或改一段

1. 作者写正文或给出本章目标；助手提供续写、扩写、选段润色、剧情建议、基础审稿。
2. 发送前能查看本次引用的设定、章节、段落和预算状态。作者可固定或移除可选资料；关键约束超预算时要求缩小任务，不静默丢弃。
3. 请求创建持久化任务，结果流向独立候选区；作者可以继续编辑原稿。
4. 候选完成后展示与生成基线的差异。采纳时再次校验原稿版本；一致则保存新正文版本，不一致则进入比较/重新基线流程。
5. 拒绝不影响正文；取消不删除已经输入的内容和部分候选。需要明确“仍可能已产生上游费用”。

首版不把所有任务都变成多模型会诊。规划、写作、提取和审稿是可配置任务角色，可以使用同一 Provider，也可以选择不同模型。

### 4. 从正文到正史

“采纳候选”和“确认为正史”分开。前者改变工作稿，后者确认该章节版本作为后续故事依据。

确认面板展示该正文版本、事实/人物状态/伏笔变化、引用与尚未核实项。可由 AI 提取候选事实，也可人工填写；只提交作者选择的条目。没有整理出的事实可以保持空集合，必须明确“尚未整理”，不能让模型补造。后续检索仍可使用该版本原文。

确认事务一起保存章节指针、正史修订、选中事实、失效标记和事件。索引投影可以重建，正文和确认记录必须保留。

初版正史按连续章序建立；跳跃写作的草稿可以提前保存，但未来计划不能绕过缺失前文进入自动续写依据。插叙仍按正文披露顺序管理，故事时间另存字段。

### 5. 修改已经确认的前文

例如改写第 3 章，而第 10 章已经写完：

- 保存新的工作稿不会改掉旧版正文；界面明确“正史修订待确认”。
- 从第 3 章起的默认记忆投影标为待复核；旧正史快照仍可在历史视图查看。
- 默认停止依赖这一段正史的自动后续生成，避免悄悄使用旧事实；仍可手动编辑与改写本章。
- 重新确认第 3 章后，更新正史修订、重建相关来源，再显示第 4—10 章的影响清单。旧文不会自动重写，受影响章节逐章复核/确认后恢复有效范围。
- 不想采用这次修订时，可从旧正史创建新的工作版本以取消修订；实验稿保留在版本历史中。

P0 采取保守的“受影响后缀失效”策略。P1 再根据明确依赖图缩小影响范围，不能先靠猜测跳过重建。

### 6. 审稿与记忆管理

问题类型至少区分：事实冲突、角色知识越界、时间/位置疑点、伏笔处理、重复与节奏建议。问题显示“疑似/需核实/作者确认”，不使用没有依据的百分制裁决。

每项结论包含本次待审文本位置、前文依据、简洁解释与建议。没有足够证据时只提问；缺少记录不等于前文一定没有发生，更不等于剧情错误。

作者可标记“确有问题”“有意安排”“误报”“稍后处理”，并说明适用章节和理由。此决定也绑定版本；换稿后不能无限沿用旧豁免。

人物档案将固定设定、某故事位置的状态、已知/未知信息分别展示。伏笔可手建或从正文提出，包含埋设来源、关联人物、预期处理范围与回收依据；“尚未处理”和“作者保留悬念”不是同一种状态。

### 7. 导入、导出与迁移

P0 导入 TXT/Markdown，先预览编码与章切分结果，支持“第X章”和手动修正；错误编码不能静默替换丢字。UTF-8 优先，旧中文编码需明确选择并预览。

已有手稿先作为草稿导入，不自动全部判为正史。导出可选择当前工作稿或已确认版本，标明范围，下载前展示章数和版本策略。

TXT/Markdown 用于正文交付；完整工作区备份保留正文、版本、设定、正史、提示词绑定与任务元数据。备份默认不包含密钥、临时网络响应和无关本机绝对路径。恢复到新目录，验证后再切换。DOCX/EPUB 是 P1。

## 功能优先级

| 级别 | 功能集合 | 完成条件 |
| --- | --- | --- |
| **P0 必须** | 书架/作品/章节、可靠编辑、自动保存与版本冲突、TXT/MD 导入导出、备份恢复 | 无模型可独立完成写作工作 |
| **P0 必须** | 演示与真实 OpenAI-compatible Provider、任务状态/事件/部分稿、候选对比采纳、取消与中断、上下文和费用状态 | 完整 AI 候选闭环，无假接口或静默覆盖 |
| **P0 必须** | 基础简报/大纲/人物/世界/伏笔、正史确认、引用校验、中文检索、依赖失效、基础审稿 | 能解释“本次依据什么”，前文改动后不混用过期事实 |
| **P0 必须** | 桌面/窄屏核心流程、中文输入法、键盘操作、错误状态、本地访问安全、可重复验证 | 满足首版工程验收；未完成项不得伪装 |
| **P1 增强** | 更精细的记忆依赖、可选语义检索、原生 Anthropic/Gemini 等适配、关系图、节奏/伏笔视图、风格指南、DOCX/EPUB、受控多章批次 | 有 P0 的使用反馈与测量依据 |
| **P2 扩展** | 替代剧情分支、多人协作、账户与云同步、桌面封装、权限工作室、插件与工具调用 | 独立产品/安全设计及部署范围授权 |

首版不包含自动发到小说平台、自动签约变现、训练专用大模型、海量模板商店、自由执行脚本的插件系统。

## 文风与内容质量

文风由叙述距离、句式节奏、对白比例、感官密度、信息披露、情绪表达与作者自己的示例定义。用少量可解释约束替代不断增长的禁词表。

目标是减少重复套路、空泛总结、视角跳跃和违背人物动机的情节，同时保留作者可有意使用这些手法的权利。不能把自动替换词语包装成“去 AI 味”质量保证。

资料库的来源、使用目的和权利声明可记录；首版不提供未经授权抓取整站小说的功能。作品名检索、历史资料查证与联网研究不是自动写作的隐式行为，后续加入时需明确来源和边界。

## 非功能目标与评测

所有数字是未验证目标，使用条件见 [验收文档](ACCEPTANCE.md)：

- 数据：已获服务确认的保存，在刷新、进程重启和正常恢复后能取回；冲突不丢任一版本。
- 编辑：在约定的参考设备与万字单章样本下，输入交互目标 INP p75 < 200ms；生成延迟单独报告，不混入本地编辑指标。
- 检索：覆盖两字中文名、别名、章节修订和作品隔离；无匹配如实显示。
- 恢复：任务明确区分可恢复检查点与未知上游执行，恢复路径有自动化故障注入证据。
- 模型：通过相同题目的人评和来源校验报告效果，不在评测前承诺矛盾减少比例。

下一阶段须验证的关键假设：作者能否理解“正文/正史”；确认事实的额外步骤是否值得；信息不足时阻止自动续写是否会过度打断；简洁上下文是否比全量堆叠更经济。通过任务观察和相同预算对照实验调整产品，而不是只依据团队主观偏好。
