# 验收、故障验证与模型评测

本文件描述持续验收方法与目标。0.1.0 已有应用与部分自动验证，证据和未覆盖项见 [IMPLEMENTATION.md](IMPLEMENTATION.md)。下列编号不是已全部通过的清单，真实模型质量仍需独立评测。

## 工程验收用例

| 编号 | 场景与动作 | 必须观察到的结果 | 首次检查方式 |
| --- | --- | --- | --- |
| A01 | 无 API Key，新建作品与章节，输入正文 | 可写、可保存、可导出；AI 操作如实提示未配置 | API 集成 + 浏览器 |
| A02 | 文本显示服务确认“已保存”后刷新、重启 | 精确恢复该版本与段落；草稿恢复副本不替换已确认数据 | 临时 SQLite + 进程重启 |
| A03 | 两个页面从同一基线修改、制造乱序保存 | 只有合法基线能推进指针；另一个报冲突并保留两份内容 | 并发集成 + 浏览器 |
| A04 | 连续拼音组合、选词、回车、撤销、换章 | 不提前提交、不误触发生成、不跳字，不因查询刷新重置光标 | Windows 中文输入法人工验证 |
| A05 | 导入 UTF-8/明确指定的旧中文编码，修正章切分 | 预览与结果一致；未知编码不静默吞字；可撤销/重新导入 | 原创样例 + 浏览器 |
| A06 | 导出工作稿/已确认稿，备份后新目录恢复 | 范围明确，正文、版本、正史映射与哈希一致，原工作区保留 | 实际备份恢复集成 |
| A07 | 生成过程中编辑原稿，再采纳旧候选 | 不覆盖新文本；显示基线冲突，可比较并人工重建基线 | 浏览器 + API |
| A08 | 相同幂等键重复提交生成与采纳 | 一个逻辑任务/一次版本推进；同键不同内容报错 | 数据库约束 + 并发集成 |
| A09 | 生成中断网，恢复 SSE/刷新页面 | 事件序号连续或快照恢复；不重新发送模型请求 | 可计数本地协议服务器 |
| A10 | 请求派发后 worker 崩溃/流中断 | 状态为 `interrupted_uncertain`，保留片段；没有作者选择不重发 | 故障注入 |
| A11 | 取消与成功返回同时发生，旧租约稍后提交 | 取消生效后不能出现可采纳迟到稿；终态不会被旧事件覆盖 | 控制时序的集成测试 |
| A12 | 限流/鉴权/超长/非法 JSON/引用错误 | 分类处理，有上限重试；错误不变成成功或正史 | 本地协议服务器 |
| A13 | 达到调用次数、输出/修订或费用预算；usage 缺失 | 停止新调用；未知不记作零；价格缺失不承诺金额上限 | 预算领域 + 协议集成 |
| A14 | 引用错误版本、错作品、越界段落、emoji 范围 | 拒绝作为有效依据；合法引用能精确定位 | 共享跨语言样例 |
| A15 | 两本书有同名人物，伪造另一作品 ID 检索/读取 | 读写和检索均不泄露另一书，不能只靠 UI 隐藏 | API/检索集成 |
| A16 | 搜索两字名、别名、中英混排和无匹配词 | 短词回退有效；不把 FTS5 未命中伪装成没有相关内容 | 中文检索集 |
| A17 | 第 3 章已确认，再保存修订，随后准备第 10 章 | 旧后缀投影无效，自动续写说明待复核；旧正文可查 | 正史集成 + 浏览器 |
| A18 | 重建索引、重复提取或重试正史确认 | 幂等，旧片段不累积，事实与确认版本一致 | 临时 SQLite 集成 |
| A19 | 将未来计划、推测或他人私密知识送给提取/审稿 | 不自动成为既成事实或角色知识；缺证不判确定矛盾 | Schema/规则 + 模型分开评测 |
| A20 | 离线、保存失败、磁盘写入错误、数据库忙 | 明确“未保存”，保留缓冲/恢复入口，不谎报保存成功 | 故障注入 + 浏览器 |
| A21 | 长标题、万字章节、长目录、窄屏与键盘操作 | 正文/面板可滚动，动作可达、焦点合理，不横向挤压 | 浏览器人工 + 截图 |
| A22 | 导入损坏/未知版本备份、越界归档路径 | 在新目录验证并拒绝损坏包，不覆盖现有工作区 | 恢复集成 |
| A23 | 假凭证标记进入连接/错误/导出与打包检查 | 前端 bundle、URL、日志、归档不含该标记；密钥无回显 | 安全回归，不读取真实密钥 |
| A24 | 外站 Origin、伪造 Host/跨作品资源访问本机写入 | 服务拒绝，默认无公网绑定；合法同源会话可用 | API 安全回归 |

文档、小样式调整不必跑全部用例；涉及版本、取消、正史或备份时必须覆盖对应关键场景。临时测试数据库与文件必须位于已核实的临时目录，禁止使用用户真实作品做破坏性实验。

## UI 体验检查

以 [UI 设计规范](design/DESIGN.md) 与 [WCAG 2.2](https://www.w3.org/TR/WCAG22/) 为目标，不能仅凭截图声称合规。

- 视口：1440×900、1024×768、768×1024、390×844；额外检查 200% 缩放和长中文标题。
- 核心动作：新建、输入、保存、查看来源、取消、采纳、恢复、导出都可用键盘完成；关闭面板焦点回到触发处。
- 主要触控目标建议至少 44×44 CSS px；状态同时用文字/图标表达；焦点不能被固定栏遮住。
- 普通文字对比度至少 4.5:1，图标与控件边界按相应 AA 要求检查。自动扫描与人工阅读分别记录，不能把单个工具分数当全面合规证明。
- IME 人工验证必须使用实际中文输入法。浏览器自动填充成功不等于输入法组合事件正确。
- 图片里未表现的错误状态、密钥为空、费用未知、版本冲突与内存重建也要验证。

## 模型评测：将流程和文学效果分开

### R1：结构与来源

建立 **48 个自创或已获授权的中文微场景**，目标构成为：24 个真实矛盾，12 个有因果依据的正常变化，12 个证据不足/计划/视角边界场景。样例应覆盖悬疑、现实和幻想题材。

这些是待创建的评测集要求，本轮没有准备 48 个样例，也没有跑分。

示例情境：

- 原文未获知姓名，后章却说“他早就知道访客是谁”：检查是否存在获知事件，而不是见到名字就判矛盾。
- 角色第 2 章受伤，第 3 章经过治疗，第 4 章可以奔跑：应作为有因果依据的变化。
- 第 20 章计划角色死亡，第 7 章仍活动：计划不能当作已发生死亡。
- 叙述者揭露秘密，但主角不在场：不能自动更新主角已知内容。
- 一段旧版正文改掉人物所在地：旧事实不得再支持当前结论。

至少两人标注标准答案与来源，不一致项经讨论定案并保留理由。按类型划分调优/保留集，例如 32/16，避免把所有题目直接写进提示词后报告“泛化成绩”。小样本结果同时给出分子、分母和不确定性，不只给单一百分比。

分别报告：

| 指标 | 定义 |
| --- | --- |
| Schema 有效率 | 通过完整结构校验的响应 / 所有响应；同时记录重试次数 |
| 引用存在率 | 版本、段落、范围、原文校验成功的引用 / 所有引用 |
| 引用支持率 | 人评认定依据支持结论的条目 / 已评条目 |
| 矛盾 precision/recall | 以人工标签为准，分别报告误报和漏报 |
| 未知校准 | 缺证时是否明确不确定，没有把猜测写成事实 |
| 规则遵守 | 计划不混事实、知识不越界、不同作品不混用 |

引用校验测试可以要求样例全通过，但不能推导真实模型语义正确率 100%。模型自己给出的 confidence 不是评测答案。

### R2：长篇连续创作对照

先使用同一套原创故事简报与相同模型/参数，比较三个上下文方案：近期正文、允许预算内的较多原文、分层来源记忆。各组总调用额度和最长输出约束一致，完整记录实际成本差异。

任务至少含十章、伏笔、人物秘密与一次前文改写；样本规模在试运行后再决定，不用单本的结果给全行业排名。

人工盲评维度：人物动机、因果与连续性、信息披露、场景变化、对白辨识度、节奏、重复表达与阅读吸引力。顺序随机，不能让评审看到模型名或方案名；记录修改耗时、采纳率和需要重写的段落数。

结果要同时展示：文本质量、误报负担、作者返工、延迟、调用次数与费用。记忆方案更贵但未改善体验时，应允许简化或关闭，而不是为了符合架构预期隐藏结果。

### R3：真实 Provider 兼容性

记录服务与模型、日期、协议能力、成功/失败、返回 usage 是否可靠、流取消表现、结构化输出与长度上限。只报告实际测过的组合；“OpenAI-compatible”不能代表所有服务都兼容。

没有本地凭证或本次调用授权时，报告“未进行真实服务验证”，通过本地协议服务器继续检查工程路径。不能为填满表格偷偷使用付费服务或第三方中转商。

## 性能目标与方法

以下均为待测目标，不是本轮成绩。先记录实际参考机 CPU/内存、系统、浏览器、构建模式、数据库规模、是否冷启动及后台负载。

- 编辑样本：万字单章，连续输入、选区、撤销与自动保存；关注长任务、输入延迟与光标稳定。产品长期目标 INP p75 < 200ms；实验室观测与真实使用 INP 分开报告。
- 资料样本：用明确标记的合成语料构造约百万字、约 300 章工作区，测目录滚动、章切换与检索；合成数据只用于性能，不能充当文学效果证据。
- 检索初始目标：约定参考机和本地数据库上，暖缓存固定查询集 p95 < 300ms；冷缓存和索引构建单独列出，超时如实记录。
- 内存与启动：记录稳定使用和长时间运行后的占用，不先编造启动秒数或“百万字不卡顿”的承诺。
- 网络与模型：TTFT、正文生成速度与费用独立测量，不能用本地 UI 快速反馈掩盖上游真实等待。

## 发布前记录格式

每项记录至少包含：代码版本、环境、日期、样本/操作、预期、实际结果、证据位置、未覆盖范围。代码变更后重跑相关检查，不能重复引用旧截图充当新版本验证。

交付说明区分：实现完成、自动检查通过、人工操作确认、真实模型验证、文学效果评测。未做写“未做”，失败写失败及影响；证据充分后停止扩大无关测试。
