# 写作中找灵感与助手结构改进

2026-10-24。沿用 0.2.0 / V4 的写作工作区，围绕“剧情卡住后怎样继续”实现一个完整流程，不更换技术栈，无新增依赖或数据库迁移。

## 实际功能

1. 写作助手增加“找灵感”，提供五种卡点，可不填补充要求。提交前保存当前稿，沿用模型选择、费用预估、持久化任务、停止、有限重试与刷新恢复。
2. 结果提供简短诊断和三个方向，每个方向有具体事件、动机、人物选择、代价、后续节点、待补充铺垫与前文依据。详情默认收起；依据逐字校验，未知来源或伪造引文拒绝作为完整结果。
3. 桌面在中央候选页签查看“剧情灵感”，正文独立保留。手机在既有助手中单列阅读，提交与完成后定位结果；正在输入时不自动定位。
4. “用这个方向续写”只准备续写，并显示已选方向；点击“按此方向续写”才调用模型。服务端只把选中方向加入冻结输入，不让其他候选污染后续剧情。对生成稿不满意时，可回到原来的三个方向重新选择；返回不调用模型，原候选保留。
5. 正文、作品设定或章节目标改变后，旧方向仍可查看，但直接续写被拒绝。跨作品、跨章节、未完成、已取消或被拒绝的结果不能作为方向；灵感不能当正文采纳，也不能作为记忆写入。
6. 结构化结果未完成时显示状态与错误，原始片段可下载，不把半段 JSON 当作可选择的完整方向。

所有候选方向都是未来建议。引用只证明原文存在，不能证明建议正确或必然原创；AI 是否提出三个有吸引力且实质不同的方向，仍需要真实模型和作者评估。

## Review 后落实的改动

- **章节任务恢复**：原先先取本书最近 150 条任务再在浏览器寻找本章，其他章节的任务可能挤掉当前章记录。现在 API 支持 `chapter_id`、`task`，先限制作用域再取最近记录；记忆窗口也按本章提取任务恢复。
- **列表查询**：ORM 只读取列表契约字段，不读取冻结模型请求、完整上下文和租约等详情。仍保留最多 150 条的现有列表协议，未实现完整历史分页，也未宣称百万字性能已验证。
- **提交回执丢失**：保留同一个请求与幂等键，暂时锁定要求、任务和模型，提供“确认上次提交”。确认前不能在界面改变条件后实际重试旧请求。浏览器注入“后端已接受、回执 503”验证只产生一个任务；这不等同于供应商计费恰好一次。
- **前端结构**：从 `Assistant.tsx` 拆出 `JobPresentation.tsx`、`InspirationResult.tsx` 和 `lib/useJobStream.ts`。任务记录、故事档案、规划与编辑器通过展示模块/Hook 复用，不再导入助手控制器来获取基础能力。
- **规划历史空白**：复现任务记录中全书方案与章节细纲结果渲染为空白的问题，补全结果分支，并将规划展示抽为 `ProductionResults.tsx`，供规划页面和历史记录共用。新增两项先失败后通过的渲染测试，并在连载浏览器流程末尾验证历史可读。
- **服务端结构**：`inspiration.py` 负责解析已选方向及前置校验，Provider 仍只提供模型响应，不修改正文和正史。

## 契约与视觉依据

新任务名 `inspiration`；结果 Schema 为 `InspirationResult`。`ContextInput.inspiration` 可选，只包含来源 `job_id` 和 `option_index`，不能接受前端任意拼接的方向对象。结果与实际输入由任务记录保留，`ContextOut.inspiration_title` 展示来源，`inspiration_reference` 用于刷新后返回原方向。

数据库结构不变；API 类型已从后端生成。新增结果类型需要前后端一起更新，不应把产生新任务后的工作区交给不识别该类型的旧代码处理。
