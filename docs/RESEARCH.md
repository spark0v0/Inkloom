# AI 小说项目调研与产品判断

调研日期：**2026-10-20，Asia/Shanghai**。

建议独立实现一个**作者主导、正文可靠保存、记忆能追溯到原文的长篇创作工作台**。优先解决改稿成本与长期可控性；自动批量生产作为后续能力，不能替代稳定编辑器和事实管理。

## 研究范围与证据等级

- 检索 GitHub 与 Linux DO，阅读下列 9 个仓库的公开介绍/README，核对默认分支、HEAD 与 GitHub 许可证元数据，并补看关键 LICENSE 和 InkOS 的发布记录。
- 阅读 6 个有具体写作场景或使用反馈的 Linux DO 讨论。它们是需求线索，包含作者自荐和个人体验，不是具有统计代表性的用户研究。
- **没有安装或运行竞品，没有做代码级安全审计、文学质量盲评或性能对比。** 仓库能力均指其文档声明；“借鉴”和“产品判断”是本方案的推论。
- 不以 Star、营销字数或作者宣称的并发量推导质量。也不把某模型在某个帖子中的口碑当作稳定事实。
- 分支、commit 与链接见 [来源快照](research/sources.json)。以下许可证为调研时所见标识，复用代码时仍应核对具体文件及其来源。

### 两个容易误判的细节

**同名项目需要核实所有者与版本。** NovelForge 和 MuMuAINovel 有多个实现与 fork。R03 专指 RhythmicWave 的仓库，R02 专指 xiamuceer-j 的仓库，不把其他 fork 的功能或许可证混入比较。

**搜索结果可能保留旧架构。** R01 当前主分支已改用 MongoDB，旧版在 `old`；R06 的当前 README 与搜索摘要中的 Tauri 描述不同。后续技术取舍以记录的默认分支快照和实际文件为准。[R01 版本说明](https://github.com/YILING0013/AI_NovelGenerator#backups-and-upgrades)、[R06 当前 README](https://github.com/ShadowLoveElysia/ElyHa/blob/main/README.md)

InkOS [v1.8.0 发布记录](https://github.com/Narcooo/inkos/releases/tag/v1.8.0)列出跨平台路径、章节原子持久化、状态修复和安全改稿等变更。这说明发布与恢复工程值得重视，但不能据此推导该版本仍存在对应问题或缺陷率。

## 研究推论：我们应在哪些方面做得更好

| 需求假设 | 本方案决策 | 如何证伪或验收 |
| --- | --- | --- |
| 作者最怕改稿覆盖自己正在写的内容 | 候选与正文隔离、采纳检查基线版本 | 生成过程中继续编辑；旧候选不得静默覆盖 |
| 长篇矛盾部分来自摘要/索引过期，而非只有上下文长度 | 原文版本绑定、依赖失效、有效正史投影 | 改第 3 章后，第 10 章的检索不再出现已撤销事实 |
| 人物知道什么与世界真相不同 | 角色知识与读者披露单独记录，保留获知依据 | 隐秘事件存在，但未获知角色不能被当作已知 |
| 故事计划容易被误记成已经发生 | 计划库与事实库分离；作者确认后提交正史 | 第 20 章的预定事件不进入第 7 章的事实检索 |
| 自动化如果不可见，返工会更难 | 固定阶段、引用、候选、调用记录和明确错误 | 用户能从审稿结果定位到相关正文与具体版本 |
| 模型重试可能造成重复费用与重复产物 | 持久化任务、有限重试、上游未知状态显式处理 | 断线重连不重复请求；不确定执行状态不盲目重发 |
| 资料整理本身具有价值 | 无 Key 可写、可检索、可导出，基础档案可手工维护 | 断网且无模型配置，仍能完成写作与保存 |
| 文学质量无法被单一分数代替 | 多维建议 + 人工盲评 + 返工量记录 | 同题对照实验同时报告成本、误报和作者修改量 |

以上是待验证的产品假设，不是已经证明的竞品短板或实验结论。

## 为什么选择独立实现

建议复用成熟基础组件，独立实现产品领域与写作流程。原因是本项目需要把“作者编辑优先、正史可追溯、原生 Windows 使用和可靠恢复”统一设计，而不同研究对象的数据结构、部署前提和目标差异较大。

首版不做插件市场、可视化自由 Agent 编排、独立向量服务、无界自我修订或自动发文。它们不是坏功能，只是目前没有证据表明它们比可靠写作闭环更应优先投入。

不复制竞品代码、UI 图片、角色素材或运行时提示词。未来若决定采用某项目代码，另行记录具体文件、commit、LICENSE 和归属信息；本报告不是对未来复用方式的授权结论。

## 还不能下的结论

- 无法给出“效果最好”的仓库排名，也无法保证百万字仍然连贯。
- 无法承诺确定收益、平台过审或通过所谓 AI 检测；本项目不以绕过检测为目标。
- 尚未选择最终写作模型、预算和目标硬件；模型能力、延迟和价格应通过本项目相同题目的评测再决定。
- 尚未验证作者愿意维护多少设定，自动提取的记忆是否确实节约时间，以及误报处理是否轻松。

接下来的关键证据是：用一个真实可运行的 P0，让作者连续完成十章并修改前文，观察正文安全、记忆更新、返工时间与实际账单。[产品方案](PRODUCT.md)、[评测方法](ACCEPTANCE.md)将这一目标具体化。
