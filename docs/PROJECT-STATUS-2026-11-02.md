# Inkloom 当前评价与编辑细节复查

2026-11-02 开始，2026-11-03 收尾。基于 `1870ba7` 继续开发，开始时工作区干净。本次检查集中于前端写作、响应式与历史恢复，并结合当前任务、上下文和数据保护代码评估产品现状。保持 **0.2.0 本地测试版**；没有真实收费调用、作者正文或密钥外部测试。

## 当前判断

**已有较完整的作者创作闭环，适合进入受控试写。长期连载可用性仍需真实作者与模型验证。** 目前最有价值的工作是降低创作摩擦、核实连续性与返工成本，以及测量大作品行为。

| --- | --- | --- |

本次构建的编辑路由约 **502 kB 压缩前 / 156 kB gzip**，Vite 给出大于 500 kB 的提示。该路由包含富文本编辑能力；此数字没有测量首屏耗时，后续应先分析模块与交互性能，再决定拆包方式。

## 本次优化

1. **P1：历史恢复的不确定回执。** 冻结原请求并确认同一次恢复，等待时禁止切换/关闭，回执后核对当前章节；若已有后续稿件，明确查看最新正文，保留其定稿状态。沿用本地缓冲区比较保护。
2. **P2：格式反馈。** 提取 `ManuscriptTools`，使加粗/斜体随光标更新，撤销/重做表达真实可用状态，组合输入期间禁用按钮。
3. **P2：历史阅读与操作。** 预览独立滚动，手机不再把正文挤进狭窄侧栏；底部操作始终可达，增加所选稿下载、当前/定稿标记与空白恢复提示。
4. **P2：响应式断点与控件裁切。** 统一外框、目录和助手的可见规则，修复中等宽度空列、目录收起无效与专注模式未铺满。工具栏分组换行、手机主要控件 44 px，字体选择与助手入口完整可达；增大手机正文空间，统一标题字体并减少按钮装饰。新检查逐项比较控件与工具栏边界，避免仅检查页面总宽而漏掉内部裁切。

独立提取历史窗口以收敛异步职责，复用已有设计与 API。没有更换框架、全局改版或数据库变更。契约见 [ADR 0029](decisions/0029-manuscript-tools-and-version-recovery.md)。

## 后续优先级

1. **真实试写与作者反馈。** 获得模型调用授权后，按同一故事连续试写 3—10 章，记录剧情连续性、人工修订量、等待和实际费用。当前授权只覆盖工程与演示验证。
2. **规模基准。** 用隔离样例测量目录、搜索、上下文组装、版本列表与长章编辑；先定位慢查询和渲染，再决定缓存或索引。
3. **持续可用性。** 基于实际操作记录继续减少重复准备、窗口往返和难理解的失败恢复；保持无模型时的手写、保存和导出路径。
4. **维护成本。** 在触及相关模块时逐步收敛 CSS 覆盖与异步职责，补持续检查；不一次性机械重写稳定流程。
