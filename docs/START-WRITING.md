# 开始用 Inkloom 试写

当前可以按“作者审阅、逐章定稿”的方式开始。先写完同一部作品的前三章，通读修稿后再扩大到十章。本指南不是模型已经通过真实验收的记录。

最新工程修复与结项判断见 [连续创作流程复查](REVIEW-WORKFLOW-2026-10-31.md)。再次打开定稿会恢复作者已确认的记忆；定稿结果未确认时用“确认上次定稿”重放原请求。出现记忆冲突时，本页选择会保留，先比较最新记录再决定是否重新编辑。

## 开书

1. 双击根目录 `启动 Inkloom.cmd`。更新代码后，已有服务需先正常停止再启动。
2. 在模型设置填写自己的服务、模型 ID 和密钥；按实际能力填写上下文容量、输出上限、流式和 JSON 能力。演示模型只体验流程，不用于成稿。
3. 新建作品，写清故事想法、题材、目标读者与核心矛盾。生成全书方案，检查主角动机、世界规则和结局方向后再采纳。
4. 先规划第一卷前五章，不必一次铺满全书。逐章编辑细纲，至少说清目标、阻碍、关键选择和结果；计划不等于已经发生的事实。

细纲卡在动机或情节衔接时，打开“大纲与章节 → 规划讨论”，选择一至三章参考，与模型逐轮推敲。讨论只读取所选细纲、书卷规划与最近成功讨论，不读取正文；修改建议先对照原稿、勾选字段后采纳。正文中的局部卡点仍可使用“找灵感”。

## 每章重复同一条路径

1. 确认细纲，生成整章。查看本次模型与资料；关键旧情节在“本章参考”明确指定有效定稿。
2. 通读候选后采纳，检查重复、凭空获知秘密、人物动机和剧情推进。
3. 局部问题优先选段改写，或从审稿意见准备对应段落修稿；卡走向时使用“找灵感”，选择方向后再续写。
4. 完成后点击“本章定稿”。可以让 AI 整理记忆，核对引文后确认；也可直接定稿，仅将原文用于后续写作。
5. 进入下一章。修改早期定稿后按提示复核下游，不能继续把旧事实当作当前依据。

可在本次要求中补充，具体情节仍以本章细纲为准：

> 紧接最近已写剧情，让人物通过行动、对白和选择产生后果，避免复述前文。不要提前解释后面的全部秘密，结尾留下与本章行动有关的未解问题。只输出正文。

## 三章后再扩大

记录每章实际字数、删改范围、人物或情节断裂，以及服务显示的用量和费用；缺少价格或 usage 时保留未知。若大部分正文需要重写，先调整故事方向、细纲、文风或模型，再继续。

达到自己的通读标准后扩展到十章，重点检查早期伏笔和人物状态。先备份作品，再打开“连载导出”：默认仅纳入已定稿，可指定当天所需的起始—结束章序，查看实际字数和未纳入原因，再下载 TXT、Markdown 或按章 TXT 压缩包。稿件若在预览后发生变化，刷新清单后再下载。发布由作者自行完成；平台接收要求以发布时的官方说明为准。

超时、截断或连接异常时先查看保留片段和调用状态，避免连续重试。上下文过大时看预览及未纳入说明；必要资料仍超限则选更大上下文的模型或缩小任务，不要填写虚假的模型容量绕过检查。
