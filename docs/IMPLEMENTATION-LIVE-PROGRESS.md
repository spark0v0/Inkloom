# 活跃生成的轻量同步

2026-10-27，Inkloom 0.2.0。参考开源项目的具体代码组织，改进生成期间的读取与连接生命周期；[来源与取舍](REVIEW-2026-10-27.md#补充流式状态与代码结构)、[契约](decisions/0013-live-job-progress.md)。沿用现有 UI，无新依赖和数据库迁移，当前迁移仍为 `d95f4b207c83`。

## 已完成

- 新增只读 `GET /api/v1/jobs/{job_id}/progress?novel_id=...`，显式查询当前片段、状态及必要变化字段。排除冻结上下文、结构化结果和历史调用正文，沿用作品归属、会话及工作区检查。
- SSE 建立连接和轮询只读取状态/事件，不再为了验证归属而反复加载完整 Job。原事件序号及重连协议保留兼容。
- 前端 `jobProgress.ts` 管理通知合并、单请求执行、缓存更新、终止详情、定时补偿和清理；`useJobStream` 只负责 React 生命周期。写作助手、策划生成和生成记录共用，移除各自 600/900 ms 的完整详情轮询。
- SSE 通知约 500 ms 合并一次，读取有最长等待；另每 5 秒读取持久化进度作为补偿。快照替换当前片段，不盲目追加历史 delta，因此重复通知不复制正文。
- 仅同任务、同作品、调用次数及更新时间不早于缓存、且仍活跃的快照可更新片段。迟到进度不能覆盖已取消状态或重试后的新状态。
- 任务终止或暂停时，先读完整详情再显示最终结果、历史及可采纳操作。读取失败保留已有片段、展示同步状态并继续只读重试，不重新生成。离开页面关闭 SSE、定时器与浏览器读取，不发送任务取消请求。

历史调用内容在完整详情中提供，活跃进度不更新历史列表正文。旧 `/jobs` 列表仍保留兼容，策划列表和历史摘要也有各自的刷新策略；本次不能声称所有历史读取都已变成轻量接口。尚未测量真实百万字作品的整体性能。

## 核心验证

- 后端 2 项：临时 SQLite 的真实 SQL 投影、跨作品隔离、SSE 状态/事件读取、HTTP 只读和工作区身份。构造含超过 100 KB 历史内容的完整详情时，进度样例小于 1 KB；这是固定样例的响应大小断言，不是通用性能百分比。
- 前端 7 项：高频通知合并、在途读取串行化、重放不重复追加、较旧/跨书/终止快照拒绝、完成事件等待、最终读取失败、断线补偿、旧完成响应遇到新重试、离开清理，以及读取恢复后清除旧错误提示。
- 浏览器 4 个场景通过：桌面正常同步和阻断 SSE 后采纳、手机阻断 SSE 后采纳、原有桌面 AI 开书→细纲→整章→记忆定稿→下一章→连载导出。正常与断线用例均断言只创建一个任务，完整详情读取不超过初次/完成两次，进度请求真实发生。
- API 类型重新生成，TypeScript/生产构建及相关 Ruff 检查通过。本地服务已更新，健康检查和新路由可用，未修改作者小说或执行新迁移。

前端假时钟测试初次有两处时序断言需多推进一个事件循环；后端新夹具初次漏填必需 task、大小断言初次按字符而非 UTF-8 字节计算。已修正并重跑对应检查。策划测试第一次筛选表达式误加标题起始锚点，未选中用例；修正筛选后实际流程通过。策划浏览器日志出现一次断开连接的 `WinError 10054`，用例本身完成通过，未隐藏该输出。详细命令见 [验证记录](verification/2026-10-27-live-progress.txt)。

未重跑全套测试，未调用真实写作模型。本轮证明读取行为、恢复与演示流程，不证明供应商稳定性、小说质量或真实大作品性能。
