# 编辑入口基线与迟到回执

2026-10-28。复查细纲闭环时发现，回执确认返回历史快照，可能把界面退回后来已被修改的版本；旧章节信息和规划 HTTP 编辑入口也没有要求读取基线。先补全这些边界，再扩展聊天工具。

- 操作回执与当前状态分开：OutlineState 增加可选 operation_revision，确认已执行的保存、恢复、采纳时返回服务端当前细纲及原操作修订号，不再次执行操作。
- 若操作修订落后于当前修订，界面保留作者输入、显示当前版本供比较，不自动推进本地写入基线；作者明确读取最新内容后才能决定合并或放弃。
- 章节 HTTP 更新要求 base_outline_revision 和 base_volume，正文自动保存不会导致细纲基线误冲突。规划 HTTP 更新要求 base_updated_at。缺少基线拒绝，真正无变化的确认请求可返回当前状态。
- 章节信息、规划编辑在打开时冻结基线，并记录作者实际改动的字段。读取最新状态后只重放这些改动，不把未编辑的旧内容一起写回。保存期间锁定输入和关闭操作。
- 细纲编辑采用原基线、本地输入、当前细纲的按字段合并：作者未改的字段使用当前值，双方都改的字段仍保留作者输入供比较；自由文本与字段格式不一致时必须明确选择，不自动转换或推进写入基线。保留哪种格式后仍须点击保存，另一版本保留在历史。
- 比较后主动放弃本地修改，采用已读取的最新细纲并清除格式冲突状态；不能只隐藏提示而保留保存锁定。
- 业务内部兼容方法仍可用于已受事务控制的可信流程；所有公开 HTTP 编辑入口采用新契约。新增单条规划读取供冲突比较使用。无数据库迁移、无新依赖，复用已有弹窗和概念图。

参考 NovelForge 的精确原文补丁预览，以及 AI_NovelGenerator 的变更修订、回执核对与作者审核；只学习组织方式，不复制第三方代码。源码快照与复现结果见本轮审查记录。
