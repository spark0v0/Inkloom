# 写作中寻找剧情方向

2026-10-24。在现有写作工作区加入“找灵感”，用于卡剧情、过渡生硬、缺少冲突、人物动机不足和情节重复。沿用持久化任务与候选结果，不新增主要导航或改变正文编辑方式。

## 交互与契约

- `inspiration` 是结构化生成任务，使用策划默认连接，先保存当前正文基线再提交。结果包含简短诊断与恰好三个候选方向，每条包含事件、动机、选择、代价、情节节点、需要补充的铺垫和可校验原文依据。
- 候选方向均为尚未发生的创作建议。依据必须来自本次冻结上下文，不能把新设定或未来计划当成已发生事实。无法提供依据时明确展示“暂无原文依据”。
- 点“用这个方向续写”只准备下一次写作请求；作者点击“按此方向续写”才调用模型。服务端从已完成灵感任务读取选中方向，检查同作品、同章节、正文版本和上下文修订，不信任前端传入的方向正文。
- `ContextInput.inspiration` 仅包含 `job_id` 与 `option_index`，只允许用于续写/改写。冻结方向与来源任务标识随新的任务保存，未选中的方向不加入生成输入。
- 生成稿保留方向来源引用，刷新后仍可回到原来的方向列表重新选择。返回只读取任务，不触发生成，不删除此前候选；原文变化后的旧方向仍按版本约束处理。
- 灵感生成、选中方向都不改变正文、章纲、正式记忆或人物档案。正文仍需审阅采纳，保留旧版本。原文或设定修改后，旧方向可查看，但须重新生成才能直接使用。
- 桌面在当前中央候选页签通读方向；手机沿用单列助手。先生成新的内容概念图，再实现；复用 V4 视觉 token、目录和导航。

## 结构与恢复

- 拆分助手中的结果展示、上下文展示与流状态 Hook，避免编辑器和任务记录依赖助手控制器。
- 任务恢复查询先按作品和章节限定，再取最近记录；避免本书其他章节的大量任务挤掉当前章结果。列表 ORM 查询不读取冻结请求等详情字段。
- 未完成的结构化输出显示状态，保留原始内容供下载，不将半段 JSON 当成可选方向。

## 验证

独立 SQLite 与 Demo/模拟传输验证方向结构、引用伪造、跨作品与跨章节隔离、版本失效、取消、恢复、正文不变、选中方向的冻结输入和候选采纳。浏览器检查桌面与手机完整流程、未保存稿先保存、错误与过期反馈。真实模型的创意质量另行验证，工程测试不代表文学效果或签约能力。
