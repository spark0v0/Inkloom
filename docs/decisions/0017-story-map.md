# 0017：从现有章节与伏笔记录投影故事脉络

状态：采用。2026-10-30。

## 问题与选择

章节细纲、定稿状态和伏笔记录已有可靠来源，但作者需要来回切换目录与档案才能看清剧情推进。参考 Novelcrafter 的 Outline/Matrix 视图，先提供按章顺序浏览和筛选的“故事脉络”，复用现有细纲编辑器与伏笔详情。持续聊天、场景级生成和多章改纲仍是独立的后续工作。

## 契约

- 脉络只投影当前作品的章节及伏笔，不保存另一份图数据，不调用模型，不根据文本相似性猜测人物关系或伏笔已回收。
- 排序采用章节 `position`；此为叙事章节顺序，不表示故事内时间。回忆、倒叙与作者的未来计划不自动转成已发生事件。
- `target_chapter_id` 只表示作者安排；暂缓、待确认和已回收状态均明确标注，计划与正文关联分别显示。
- 撤销的进展不进入默认脉络。服务端标记失效，或关联版本与当前定稿版本不一致时，显示待复核，不渲染为有效进展；失效依据仍可回看，不能据此证明当前正文。
- 标记保留既有 Evidence，原文查看继续使用指定不可变版本。未匹配到本作品章节的关联不挂在其他章节上。
- 搜索支持章名、细纲、分卷、伏笔名称与别名；可按卷、章状态、伏笔筛选。一次最多渲染 40 章，并显示真实总数与翻页。
- 进入地图及明确刷新时读现有 API，沿用按作品隔离的 QueryClient；刷新失败就近提示并保留已经取得的数据，不伪报最新。章节细纲可深链进入，返回和刷新保留地图入口；伏笔链接进入对应档案。

## UI 与兼容

先生成 `docs/design/ui-story-map-2026-10-30.png`，提示词随项目保存。使用既有灰白工作台、深青色操作和文字导航；桌面章节时间轴与伏笔索引并排，手机使用单列和下拉筛选。

没有数据库、任务、生成提示词或备份格式变更。新增路由查询参数只控制展示，未知值忽略；旧链接继续有效。
