# 0022：恢复记录与再次定稿

2026-10-31，已实施，相关工程验证完成。本地单作者部署，不改变模型调用授权或数据库结构。实际检查见 [流程复查](../REVIEW-WORKFLOW-2026-10-31.md)。

## 恢复记录

写作、细纲修改、定稿整理和分卷生产入口使用分页摘要，不读取旧的完整任务列表。任务类型集合、分卷、正文基线版本及待处理条件均在数据库分页前过滤，游标绑定全部条件；分卷与版本必须属于请求指定的作品、章节。需要查看的单个任务才加载详情，流式进度维持原有机制。

## 再次定稿

新增只读定稿准备接口，返回当前正文版本、定稿修订以及该版本已确认的记忆。重新打开已定稿章节时优先恢复作者确认的记忆，不用旧 AI 提议覆盖它。读取失败或版本变化时不能按空记忆继续提交。

修改已确认记忆需要 `base_canon_revision`，不携带或基线变化返回冲突。正文和记忆均未变化时直接返回当前状态，不增加修订、不失效下游章节。该无变更操作不新增写入回执；随后重放仍须通过当前状态/基线检查，不可借此覆盖其他作者操作。首次定稿保留旧调用兼容，新界面始终发送准备时的修订。

定稿提交后冻结正文基线、记忆、操作号及是否进入下一章。网络或服务端不确定错误后只重放原请求；明确拒绝后才能修改参数。尚未确认时阻止修改和误关窗口，保留重试入口；重新加载后从服务端读取已确认记忆。采纳回执后重新读取实际状态，迟到回执不能跳过已变化的章节。

真实模型的十章连续创作、人工返工量和费用仍需独立验收。上述工程变更不能作为“完全满足生产”的证明。
