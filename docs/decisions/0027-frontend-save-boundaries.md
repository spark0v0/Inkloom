# 0027：前端保存期间与档案冲突的边界

2026-11-01。沿用现有工作台和弹窗布局，不增加依赖、数据库迁移或真实模型调用。

- `Modal.dismissible=false` 同时阻止遮罩和 Esc 关闭；调用方在请求期间禁用取消和所有可编辑参数。中文输入法组合期间忽略提交，使用同步请求锁防止同一事件周期的重复写入。
- 档案发生冲突时保留完整原基线。读取最新档案后，作者已修改的字段继续保留，未修改字段采用最新内容，再更新保存基线；别名按统一分隔规则比较。只提交可写字段，不能把服务端元数据带回接口。遇到再次冲突时重复同样的比较流程，不自动覆盖。
- 默认连接接口当前提交四个任务的完整配置；页面串行保存，成功回执写入缓存并完成刷新后再允许下一次切换，失败在对应区域显示。该约束解决同页并发，不提供跨窗口配置修订锁。
- 速查设定的本章必读同样串行提交；最新参考读取失败或发生修订冲突时先明确重读，不能退回旧章节摘要继续写入。待确认档案允许查看，确认前不提供加入必读操作。
- 手稿导入独立为组件。文件读取、切分预览、提交期间冻结输入；读取失败清空旧文本和旧切分，按实际原因显示编码或大小错误。成功导入后若打开作品失败，保留已创建作品，仅重试打开，不能再次发送导入请求。
- 以上是浏览器交互与本机持久化验证，不代表真实输入法、所有浏览器或网络中断下的服务端写入恰好一次。正文与任务继续使用既有版本、幂等和不确定回执机制。
