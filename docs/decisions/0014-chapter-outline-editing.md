# 章节细纲编辑、历史与 AI 局部修改

2026-10-27。落实此前产品取舍的第一阶段；聊天规划与故事脉络图后续复用这些数据，不另造副本。参考 Novelcrafter 的章节/场景编辑与规划聊天分离、NovelForge 的字段候选确认，独立实现。

- 规划页直接进入单章细纲编辑；正文仍有独立入口。保存不调用模型，目标、冲突、情节节点和章末钩子按结构保存；章节 goal 是兼容文本投影。
- 旧结构化细纲按真实字段读取；旧自由文本保持全文，不使用正则静默拆字段。手动转为字段编辑时，旧内容保留在历史；只改标题或分卷不能丢弃结构。
- 新增细纲修订号与不可变历史表。首次变更先保存旧状态，后续每次变化生成新历史；相同操作号内容一致可确认重试，冲突保留草稿。恢复历史也是新修订，不替换正文或已定稿事实。
- 原章节/规划接口保留兼容，关联章节走同一同步服务。显式改旧 goal/body 才视为自由文本编辑；正文保存与无关元数据变更不制造细纲修订。
- AI 修改复用持久化任务，增加 outline_edit 类型。冻结当前细纲、修订和作者选中的字段；校验输出不能改未选字段、标题或文档类型。采纳重验正文、设置及细纲基线。
- 作者逐项采纳，服务端仅应用选中变化并记录来源。采纳与恢复不调用模型；细纲变化递增设置修订，沿用旧候选失效机制。
- 迁移只增加修订号和历史表；备份核验归属、哈希、连续修订和投影，兼容前五版归档升级，保留原工作区。
- UI 先生成 [概念图与提示词](../design/UI-CHAPTER-OUTLINE-IMAGE-PROMPT.md)，手机采用页签，复用现有组件，无新依赖。

核心验证覆盖结构保留、冲突、恢复、字段范围、迟到采纳、备份升级和两端流程；不调用真实写作模型。
