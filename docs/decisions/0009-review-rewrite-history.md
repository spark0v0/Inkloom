# 从审稿问题到段落修订，并找回完整生成历史

2026-10-25。沿用 SQLite、持久化 Job 与 V4 工作区，不复制竞品代码，不新增数据库迁移或依赖。

## 审稿与修稿

- 审稿在中央“审稿意见”页签通读；手机沿用助手单列。每条意见展示待审原文、依据、解释和建议，作者判断与说明收起。
- “准备改写这一段”只保存作者已经编辑的稿件并读取准备结果，不调用模型、不改正文。服务端根据指定版本、稳定段落 ID 与可校验引文计算整段选区，保留空行与 Unicode code point 坐标。
- 已填的本条作者说明在准备修稿时保存，保留原来的作者判断；说明也可单独保存。新前端提交读取时的判断与说明基线，防止另一窗口的更新被静默覆盖。
- 作者检查段落和写作模型，明确点击“按建议改写”后才创建持久化 rewrite 任务。只将选中的问题加入模型输入；建议不是正式事实。结果仍为候选，采纳只替换该段，原稿与其他段落保留。
- 来源必须是同书、同章、已完成且仍有效的审稿。引用绑定 `job_id`、`finding_index` 与该条意见的哈希；正文、设定、参考或作者判断变化后拒绝旧准备。误报/有意安排的意见不能直接用于修稿，不能自动把修稿标成“问题已解决”。
- 修订任务冻结来源，可刷新后返回原审稿。生成期间来源变化和采纳前都检查依赖；准备和返回均不隐式调用模型。

## 完整历史

- 保留原 `/jobs` 列表协议供已有恢复入口使用，新增独立分页协议。按实际创建时间和 ID 做游标分页，绑定作品、章节、任务、状态、搜索条件；非法或错用游标明确报错。
- 新分页只读取行级摘要、作品/章节名称和有限要求预览，不加载正文结果、结构化结果或冻结上下文；打开记录才取详情。
- 生成记录页支持要求、章名和书名搜索，类型/状态筛选与“加载更早记录”。新条件从第一页读取，返回此前条件可恢复其已加载页；不同条件的游标不能混用，不能用已加载数量冒充总数。

## 验证与限制

重点覆盖准备不生成、不改稿、段落范围与 emoji/空行、版本和作者判断变化、隔离、选中意见之外不进入修稿、迟到结果、局部采纳、超过 150 条记录、同时间戳排序、筛选游标隔离与列表查询范围。前端按 V4 和先生成的功能概念图实现，验证桌面/手机与关键键盘行为。

这些是工程闭环；真实模型的审稿准确性、修稿文学效果、长篇伏笔管理与连续十章质量另行验证，不能用 Demo 代替。
