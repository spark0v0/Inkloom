# 活跃任务进度与完整详情分开读取

2026-10-27。参考 MuMuAINovel 的 chunk/result/complete 分工和 RhythmicWave/NovelForge 的流连接清理、终止事件处理；独立实现，保留 Inkloom 的服务端持久化任务和 SSE 序号补发。

- 新增只读任务进度投影，只查询当前状态、片段及必要的变化字段；不加载冻结上下文、结构化结果或历史调用正文。作品归属和工作区身份仍由服务端核验。
- SSE 只是刷新信号，不在客户端盲目累加可重放 delta。合并相邻通知，单个订阅最多一个读取请求；只将较新、同作品且仍活跃的快照合入缓存，重复或迟到信号不追加重复文字。
- 活跃状态使用轻量读取。终止/暂停时重新读取完整详情后才呈现结果、错误、历史与采纳操作，不能把进度片段冒充完整候选。完整读取失败保留已读片段并有限频率继续读取，不重新生成。
- 连接失败使用定时只读补偿；离开页面关闭订阅、定时器和浏览器请求，不取消服务端任务。SSE 读取自身也只查状态与事件，不重复反序列化任务完整上下文。
- 三个入口共享同一订阅实现，移除各自的完整详情短间隔轮询。沿用现有界面，本轮不改变主要布局，也不增加依赖或数据库迁移。

验证覆盖 SQL 投影/跨作品隔离、通知合并、迟到快照、断线补偿、最终详情失败与清理，以及隔离 Demo 的真实浏览器生成/采纳。真实小说模型仍不调用。
