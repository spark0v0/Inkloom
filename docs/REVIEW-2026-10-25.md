# 2026-10-25：热门开源项目对照与审稿修稿闭环

本轮实际核查 GitHub 仓库和 README，结合 Inkloom 现有代码选择改进。stars 是本次页面显示的约数，仅用于说明关注度，不代表模型质量；没有将这些项目的宣传或预设演示当作真实成稿证明。独立实现，没有复制第三方代码或图片。

## 在 Inkloom 代码中确认的不足

1. **审稿后仍需手动复制建议和重新框选正文。** `JobPresentation.tsx` 原来只提供判断按钮与查看来源，`Assistant.tsx` 没有审稿来源引用。新增服务端准备、选中意见哈希和真实段落范围；点击准备不生成、不改正文，作者明确生成、比较并采纳。
2. **审稿挤在右侧窄栏。** 原 `inDocument` 只包括正文与灵感。现在桌面使用中央“审稿意见”页签，手机沿用单列；解释、引文和建议可通读，作者判断收起。返回审稿和修稿候选均不再次调用模型。
3. **作者说明和判断缺少窗口间的基线检查。** 原接口直接更新索引对应条目。新前端提交读到的判断/说明，冲突保留输入；准备修稿会保存已填写说明，保持原判断，不能将误报、有意安排自动当成待修复事实。
4. **生成历史固定限制最近 150 条，难以找回旧稿。** 新增按创建时间和 ID 的游标分页，绑定作品、章节、类型、状态和查询条件。界面提供搜索、筛选及更早记录；加载失败保留已经读出的行。
5. **原列表虽然不读冻结上下文，仍读完整 `output_text` 与 `result`。** 新分页单独查询有限摘要和真实书名/章名；只在打开记录时取全文。旧列表保留兼容，不能宣称所有旧恢复入口都已改成轻量协议。

契约与实现范围见 [决策 0009](decisions/0009-review-rewrite-history.md)。本轮没有数据库迁移或新依赖；UI 先使用 imagegen 生成 [概念图](design/ui-review-revision-v1.png)，再沿用 V4 组件实现。概念图中的导航顺序、模型名和状态数字不作产品数据；作者判断按钮实际放在收起的详情内。

## 仍然需要完成的可用性门槛

| 优先级 | 剩余缺口 | 需要的证据 |
| --- | --- | --- |
| 最高 | 真实模型连续成稿与改稿质量 | 至少十章真实候选、改稿前后文、调用与费用记录、作者通读判断；Demo 与协议模拟不能证明小说质量 |
| 高 | 伏笔与人物状态随剧情演变 | 埋设、推进、回收都能定位定稿证据，前文变化后正确失效；未知、计划、事实分开 |
| 高 | 更可执行的作品文风约束 | 作者自有示例、叙述视角和篇幅约束进入生成与对照评测，不用模型自评分或禁词表当质量标准 |
| 中 | 模型兼容、免 Key 本地服务与总调用时限 | 按实际端点测试协议、鉴权、超时与长心跳，不只验证模型目录可读 |
| 中 | 外部材料库与分发 | 资料归属、引用、导入恢复和可安装包的实际测试；本章补充资料与一键脚本不等同于完整知识库或独立 EXE |

实际改动、自动检查、界面截图和未验证事项见 [实现与验证记录](IMPLEMENTATION-REVIEW-REVISION.md)。用户明确选择本轮只做工程验证，未调用真实模型。不要将“新增功能”或自动检查通过写成已经达到平台签约、长篇质量或收益要求。
