# 恢复副本与作品编辑边界修复

2026-10-29。针对本轮 review 的三个已复现数据问题和定稿进度的重复读取，沿用现有页面与概念图完成修复。契约见 [ADR-0016](decisions/0016-recovery-and-novel-edit-boundaries.md)。

## 实际修改

- 正文恢复副本按编辑实例使用独立键；同章多窗口各自写入、清理自己的副本。重新打开时显示可选择的多份副本，兼容旧版章节键，提供折叠预览与下载。存储操作按实例串行处理。
- 恢复正文前先保存本页输入，再保存选中的副本。两次保存任一失败均保留恢复材料。源副本只在保存确认后按完整快照条件清理；期间其他窗口更新了同一副本时保留新内容。输入法组合期间拒绝恢复。
- 细纲副本新增原始文档基线。旧副本从相应不可变历史读取，不能拿最新文档冒充原始基线。历史暂不可读时不恢复、不丢弃副本，提示重试和下载。恢复再比较只重放作者实际改过的字段；确认保存后按快照清理被恢复的源副本。
- 细纲编辑实例不再依赖会随复制标签页一并复制的 sessionStorage 标识；旧副本仍通过作品/章节前缀发现。
- 公开作品 PATCH 使用 NovelUpdate，要求 base_settings_revision；相同内容的确认请求不增加修订。内部 NovelPatch 保留可信业务兼容。作品改名同步全书规划时也更新规划基线，旧规划表单不能覆盖新书名。
- 作品编辑抽成 NovelBriefDialog：只提交主动编辑字段，冲突保留输入，读取最新内容后刷新未改字段。归档请求也携带设置修订，冲突时刷新列表供作者重试。
- 本章定稿弹窗移除完整任务详情的 600ms 轮询，复用 useJobStream 的轻量进度与终态完整结果。
