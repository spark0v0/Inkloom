# 规划讨论与历史读取优化

2026-10-31，保持 **0.2.0 本地测试版**。本轮实现有范围的持续规划讨论，并修复 review 中确认的两个问题。没有进行真实模型调用。

## 使用路径

1. 打开作品的“大纲与章节 → 规划讨论”，新建讨论。
2. 展开“参考细纲”，选择同一本书的一至三章，选择讨论模型，输入具体问题。
3. 可先“查看本次资料”，核对实际参考与费用估算，再发送。新讨论默认选择首章，已有讨论使用上次的参考章节。
4. 多轮推敲动机、冲突和衔接。回复如带修改建议，可对照原细纲，勾选字段并采纳。
5. 采纳只更新细纲，有改动时生成细纲历史；正文与已确认记忆不随之改写。继续讨论会读取更新后的细纲。

刷新读取已保存的对话。未发送文字与未确认请求存入按工作区、作品、讨论和编辑实例隔离的 IndexedDB 恢复副本。恢复后由作者决定重试原请求，不自动发送。独立链接支持从生成记录定位讨论，编辑细纲后返回相应讨论。

## 资料与写入边界

- 本版读取作者简报、完整选定细纲、相关书卷规划和最近最多八轮成功讨论，**不读取正文**。书卷资料每项最多 3000 字符，裁剪有提示；旧讨论是历史建议，不是已发生事实。
- 预算不足先移除较早讨论，再移除可选规划。选定细纲仍超限则拒绝创建任务。预览、消息、估算与资料指纹基于同一次组装；预览后的资料变化返回冲突。
- 每次发送复用一个 `discuss` 持久化任务，不启动自动 Agent 循环。会话头、轮次与任务入队在同一事务内更新，重放相同幂等请求返回原任务。
- 一次回复最多建议修改一个已选章节。结构化细纲只允许目标、冲突、情节节点和章末钩子；自由文本只允许改文本。格式、标题和未声明字段确定性校验。
- 采纳检查会话头、作品设置与正史修订、所有参考细纲及提案原始修订。资料变化或后续讨论出现后，旧提案可读，不可直接采纳。成功操作可重放回执，不把旧回执当作新编辑基线。
- 新接口显式绑定发起页面的工作区，阻止切换后的迟到预览、发送或采纳落入替换工作区。

## 实现与迁移

`backend/app/discussions.py` 负责范围、预算、历史和采纳；运行时模板为 `prompts/discuss-v1.md`。新建 `planning_conversations`，消息和回复继续使用 `jobs`，不另存一份正文。历史每次 30 轮，只查所需字段，不加载完整上下文；活跃状态沿用 SSE/轻量进度，取消和未知调用保持既有语义。

新迁移 **`f17b6d429ea5`** 增加会话、任务轮次与历史索引。兼容前六版备份，先校验再在新目录升级，旧备份的讨论为空；新备份校验同书引用、参考快照、轮次链和会话头。恢复按线性迁移顺序确定必需结构，新增迁移不能放松旧备份的参考、伏笔、文风或细纲历史校验；已有 `e06a5c318d94` 备份缺少这些结构时拒绝恢复。

界面复用工作台色彩、模型披露、细纲字段显示和查询缓存。先生成 [概念图](design/ui-planning-chat-2026-10-31.png)，保存 [完整提示词](design/UI-PLANNING-CHAT-PROMPT.md)，再实现。消息独立滚动，手机使用讨论选择框；资料与提案使用已有对话框交互。契约见 [决策 0021](decisions/0021-planning-discussions.md)。

## 两项已确认问题的修复

1. `inspiration` 曾遗漏兼容接口的 JSON 模式。Provider 与结果校验现在共用 `task_contracts.RESULT_SCHEMAS`，关闭 JSON mode 时仍尊重连接配置。
2. 章节历史此前返回摘要却查询完整 `Version`。现在只投影元数据，界面按 `(created_at, id)` 游标每次加载 30 条，选择后才读取某版正文。旧接口保留兼容。

## 工程验证与限制

覆盖多轮、显式采纳、字段边界、资料变更、跨作品/工作区、回执重放、取消、预算裁剪、历史分页及新旧备份。桌面和手机流程使用独立 `.tmp/e2e-*` 工作区与固定演示回复，不接触作者工作区。

手机复查发现恢复后重试按钮被输入区挤出面板，修正收缩与滚动后重新验证。主动模拟回执丢失时，Windows 测试服务记录 `ConnectionResetError: [WinError 10054]`；另有既有 Starlette/httpx 弃用和 Node 颜色环境提示。这些不作为真实供应商或文学效果的验证。
