## 确认的问题与修改

| 优先级 | 问题 | 处理 |
| --- | --- | --- |
| P1 | 全书方案/细纲在提交回执丢失后仍能改参数，确认时却发送冻结的旧要求；还可采纳旧候选或局部返回 | 同步锁防重复提交，冻结模型、批次、要求和局部返回。未知回执明确显示“确认上次提交”，原请求和幂等号保持不变；结果提前完成也不收起确认入口 |
| P2 | 引用预览的复选框只改前端排除列表，来源、事实、预算和费用估算仍显示旧值；历史引用也能修改待生成选择 | 提取 `ContextPreviewDialog`，用原预览输入调用只读上下文接口重算，成功后一起更新；保留排除项供撤销，重开后也可恢复全部自动引用。历史快照只读，失败保留上次成功结果 |
| P2 | 文风冲突只更新修订号，下一次保存会覆盖本页未改的远端字段；输入法组合也可能提交 | 保存完整字段基线，逐项合并语言、视角、避免写法与示例；连续冲突沿用新基线。保存/重读共用同步锁，组合期间不提交 |
| P2 | 长文风比较挤占底部操作，长条快捷文字占用手机编辑空间 | 比较内容移入原滚动区，保存与错误保持可达；快捷项改成短标签，完整要求仍写入表单，超过字段上限不继续追加 |
| P2 | “霸气对白”默认统一强势人设，其他微操作偏向无依据添加围观者、兵刃或战力 | 改为“对白打磨”，保留动机、关系、已知信息与结果；打斗/反应/五感指令约束在已有场景内，今后的任务冻结新要求，旧任务内容不变 |

## 工程验证

使用隔离的 `e2e-*` SQLite 工作区，生成仅使用明确标记的本地固定演示响应。提交回执测试请求真实本机 API 后才模拟丢失回执；核对确认前后请求完全相同且只存在一个任务。

- 修复前：文风未改字段、引用排除不重算、规划回执后参数仍可改，三项桌面复现失败。
- 新增回归首次补验修正了两处测试预期：服务端确认后才更新复选状态，测试应点击并等待；错误提示增加说明后按 alert 内容定位。另修正测试结束时返回正文页签再检查，保留正文不变断言。
- 前端单元测试、构建、浏览器最终检查见[验证记录](verification/2026-11-02-review.txt)。
- 人工查看桌面和手机测试截图；手机引用预算、选择、返回操作可达，长风格比较可滚动。局部检查不代表全站无障碍认证。

## 保留的限制

上下文仍采用受范围和预算约束的词法召回，后章失效仍是保守复核机制；没有升级为语义记忆或自动改稿系统。预览是某一时刻的组装结果，生成前仍重新校验，其他窗口改动可能要求重新准备。

规划未知回执的原请求保留在当前组件，整页刷新后依赖服务端持久化任务恢复；浏览器重放不保证供应商计费恰好一次。没有新增自动重试。

微操作要求调整只证明准备与传输正确，未验证真实模型文学质量、人设保持效果或实际费用。没有重跑无关后端全套测试，也未做百万字性能、完整 Windows 输入法人工或跨浏览器验收。
